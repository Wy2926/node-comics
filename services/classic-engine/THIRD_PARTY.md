# Sources and licenses

This project is GPL-3.0. Model weights are excluded from the source repository but selected verified inference weights are included in the separate Windows release described below. Operating-system fonts, private test images and generated outputs are never distributed.

- [Yakuyomi Engine](https://github.com/joyeli/yakuyomi-engine/tree/bbe574041ef1ffa2bb183424a2d4cc0830f4ed71), GPL-3.0: DBNet preprocessing and model manifest provenance (historical AOT removed); `vendor/grouping.py` derives from its `parity/mit_grouping.py`. `vendor/ocr.py` retains point ordering and greedy CTC primitives from `parity/ocr_parity.py`. CTC normalization is limited to emitted frames. The old desktop typesetting copy has been removed.
- [manga-image-translator](https://github.com/zyddnys/manga-image-translator/tree/d5a3eee4a7b7b7754b71baa2ee82309dfff468bc), GPL-3.0: original 48px CTC checkpoint, grouping and right-context padding. `tools/build_ocr.py` pins this exact revision. The original [ocr-ctc.zip](https://github.com/zyddnys/manga-image-translator/releases/download/beta-0.3/ocr-ctc.zip) SHA-256 is `fc61c52f7a811bc72c54f6be85df814c6b60f63585175db27cb94a08e0c30101`.
- Upstream was fetched and rendering/word-wrap/font fallback reviewed at [95227a2](https://github.com/zyddnys/manga-image-translator/tree/95227a2bb0fd306cd4f0c104d57284026f991b3a). The checked-out export source remains pinned to the earlier model revision. We retain region geometry and measured fitting concepts while using maintained libraries below for segmentation/hyphenation; we do not import the upstream application/server stack or its runtime dictionary downloader.
- Balloon-aware horizontal lettering was independently implemented after reviewing upstream [`ballon_extractor.py`](https://github.com/zyddnys/manga-image-translator/blob/main/manga_translator/rendering/ballon_extractor.py) and [`text_render_eng.py`](https://github.com/zyddnys/manga-image-translator/blob/main/manga_translator/rendering/text_render_eng.py). `bubbles.py` uses bounded blank components on the cleaned page and partitions neighboring regions; `layout.py` fits balanced whole-word lines inside that mask. No additional segmentation model or upstream renderer runtime is required.
- [RapidOCR 3.9.2](https://github.com/RapidAI/RapidOCR/tree/v3.9.2), Apache-2.0: directly use `TextRecognizer`, its PP-OCR normalization and CTC decoding. PP-OCRv5 English, Korean, Chinese and Latin mobile ONNX models are selected explicitly from the versioned [model catalog](https://github.com/RapidAI/RapidOCR/blob/v3.9.2/python/rapidocr/default_models.yaml). Their upstream SHA-256 values are pinned in `manhua_engine/models.json`. Model architectures originate in [PaddleOCR](https://github.com/PaddlePaddle/PaddleOCR), Apache-2.0. No additional detector/classifier is loaded by this adapter.
- [uniseg 0.10.1](https://uniseg-py.readthedocs.io/en/stable/), MIT: Unicode UAX #14 line breaks and UAX #29 grapheme clusters; Unicode data retains its upstream notices.
- [Pyphen 0.17.2](https://github.com/Kozea/Pyphen), GPL-2.0-or-later / LGPL-2.1-or-later / MPL-1.1: local hyphenation. Bundled LibreOffice dictionaries retain their individual notices. No runtime dictionary downloads.
- [fontTools](https://github.com/fonttools/fonttools), MIT: font cmap coverage. [Pillow](https://github.com/python-pillow/Pillow), HPND: FreeType rasterization. User/system fonts remain under their own licenses.

Other installed dependencies retain their upstream licenses: NCNN (BSD-3-Clause), ONNX Runtime (MIT), NumPy (BSD-3-Clause), OpenCV (Apache-2.0), NetworkX (BSD-3-Clause), Shapely (BSD-3-Clause), Requests (Apache-2.0), psutil (BSD-3-Clause) and portalocker (BSD-3-Clause). This is a Python desktop engine, not an Android/JNI wrapper; no Android Canvas pixel identity is claimed.

The separate Windows [Node Comics Node release](../compute-node/README.md) bundles inference weights verified by this engine, dependency license files, and explicit Noto fonts under SIL OFL 1.1. Font commits, download URLs and SHA-256 checksums are pinned in [assets.json](../compute-node/assets.json); it does not redistribute Windows system fonts. Its native Go host uses Go, golang.org/x/sys v0.46.0 and golang.org/x/term v0.44.0 (BSD-style licenses), with notices included in the release. The CPython runtime retains its upstream LICENSE.txt; each release records the runtime version and every bundled file's checksum. Runtime assets and private node data are separate.

## LaMa Large (2026-09-21 replacement)

- Inference classes in `tools/lama_model.py` are extracted unchanged from [manga-image-translator inpainting_lama_mpe.py at 95227a2bb0fd306cd4f0c104d57284026f991b3a](https://github.com/zyddnys/manga-image-translator/blob/95227a2bb0fd306cd4f0c104d57284026f991b3a/manga_translator/inpainting/inpainting_lama_mpe.py), GPL-3.0. Source file SHA-256: `6322a120e840b0a1c14ec5dced6e43707b873d9f504fb8a4dfe103da885b9ce6`. Application imports, downloader, discriminator/training and MPE classes are omitted. Our adapter implements checked, weights-only deserialization and local aspect-preserving /8 padding with mask-only composition.
- The upstream generator derives from [LaMa](https://github.com/advimman/lama), [FFC](https://github.com/pkumivision/FFC) and [ZITS](https://github.com/DQiaole/ZITS_inpainting); their repositories carry Apache-2.0. The license text is retained in `manhua_engine/vendor/LICENSE-lama-ancestry`; this does not replace the GPL license of the directly imported MIT-project code.
- Weights: [dreMaz/AnimeMangaInpainting model card](https://huggingface.co/dreMaz/AnimeMangaInpainting/blob/main/README.md) declares MIT and describes manga/anime fine-tuned Big LaMa. `lama_large_512px.ckpt`, 204544673 bytes, SHA-256 `11d30fbb3000fb2eceae318b75d9ced9229d99ae990a7f8b3ac35c8d31f2c935`, matches the pinned upstream `LamaLargeInpainter` mapping. Model-card license is recorded separately from application-code licenses; weights are explicitly downloaded, never committed.
- Build only: PyTorch 2.6.0 CPU distribution (BSD-style upstream license) and ONNX 1.23.0, pinned by `uv.lock`. Runtime: ONNX Runtime DirectML 1.24.4 (MIT; bundled DirectML retains its Microsoft terms), Windows GPU FP32, with CPU fallback disabled. `tools/build_lama.py` uses independently implemented separable real-valued DFT matrices, following the export approach documented by [Carve-Photos/lama](https://github.com/Carve-Photos/lama/blob/main/saicinpainting/training/modules/ffc.py) (Apache-2.0). We retain the manga checkpoint rather than substituting Carve big-lama weights, and avoid Carve's higher-rank MatMul/Einsum export which failed on the tested DirectML device. This release does not implement Vulkan LaMa.
