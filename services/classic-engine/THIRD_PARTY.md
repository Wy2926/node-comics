# Third-party sources

## Manga Translator UI

The image pipeline imports source from [hgmzhn/manga-translator-ui](https://github.com/hgmzhn/manga-translator-ui), pinned by commit, archive URL and SHA-256 in [upstream.lock.json](mtu_engine/upstream.lock.json). Preparation retains `manga_translator/`, the upstream `LICENSE.txt`, dependency manifests and checksums under `upstream/`. The project carries GPL-3.0 terms; original notices within source files remain intact.

Local source edits are recorded verbatim as ordered per-file patches in the lockfile:

- `build_det_rearrange_plan` in `manga_translator/utils/generic.py` calculates the stripe count with a maximum 80% stride, ensuring at least 20% overlap rounded down to whole pixels. Native packing, inference, feathered map merging, contour extraction and model weights are unchanged.
- `_polygon_fully_inside_mask` in `manga_translator/rendering/__init__.py` rasterizes only the clipped polygon's bounding rectangle, preserving integer conversion, clipping and containment semantics.
- `find_largest_inscribed_rect` in the same module removes only empty outer mask rows/columns before the unchanged histogram/stack search, then restores page coordinates. All components, holes and equal-area tie ordering remain intact; non-CJK bubble-mask layout stays enabled.
- The same rendering module allows the native rich-document font search to grow within an enclosing bubble instead of only shrinking to the source OCR box. The mask bounding rectangle supplies a finite search upper bound; the unchanged native glyph/mask check selects the size, retaining box-fitting as fallback. Rich words reuse the native collision guard against placed paragraphs and pending source boxes, then register their layout for later paragraphs. This applies only to bubble-mask layout; word contents, source geometry and free-text sizing are unchanged.
- `manga_translator/utils/bubble.py` selects intersecting component labels within clipped polygon bounds, while returning the complete native component union with its holes. First construction scans only the selected components' native statistical bounds. Prepared read-only labels/statistics from inpainting are page working data, separate from the optional unique-uint8-union cache budget. Different regions intersecting the same component set share a union; demand is estimated from unique nonempty sets. Cached union bounds avoid another full-page bounding scan; largest-inscribed-rectangle results are cached only for retained immutable masks. Contexts are isolated and released on exit; layout and font sizing rules are unchanged.
- `solid_fill_pure_bubbles` in `manga_translator/inpainting/ballon_fill.py` optionally accepts the already-computed native labels/statistics and bounds per-bubble sampling and filling with them. Text-box overlap retains the full box denominator, and background statistics, holes and fill-mask intersections are unchanged. The same 2% inset is reused by rendering. The LaMa loop passes existing uint8 masks directly to connected components and removes the crop copy before the owning reflection-padding copy; window order, model inputs and paste-back semantics are unchanged.
- `_complete_mask_core` in `manga_translator/mask_refinement/text_mask_utils.py` restricts diameter-17 bilateral filtering to each CRF input with an 8-pixel halo, preserving the original image-edge border rule. Line polygon areas are computed once; overlap scores use a single float32 row, and centroid/distances are only computed inside the native distance fallback. CRF inference, component assignment, tie order and dilation are unchanged.
- Bubble clipping in `manga_translator/mask_refinement/__init__.py` avoids re-binarizing uint8 component inputs and whole-page bubble masks, retains the untouched pre-clip input by reference, and only computes logging statistics when enabled. Output ownership, holes, line protection and clipping semantics are unchanged.
- `calc_font_from_box` in the rendering module normalizes stable plain text once per font search, reusing the native rich-document measurement path without changing region layout type. `TextStyle.copy` in `manga_translator/rendering/rich_text.py` copies typed scalar value objects and their mutable children directly instead of recursively traversing them.

Preparation requires an exact single match for each patch, marks the changes in source, and hashes the resulting files in the asset manifest. Other MTU source files remain unmodified. Existing assets must be prepared again; startup rejects the previous lock hash.

The lock also records the DBNet checkpoint from [manga-image-translator](https://github.com/zyddnys/manga-image-translator), PP-OCRv5 Korean weights/dictionary distributed by MTU, the LaMa Large checkpoint from [AnimeMangaInpainting](https://huggingface.co/dreMaz/AnimeMangaInpainting), and MangaLens weights distributed by the MTU author. PP-OCR reuses MTU's Apache-2.0 perspective crop and CTC decoder with published ONNX files pinned by SHA-256; no locally exported models or patched inference bindings are shipped.

Text fill and single-outline colors reuse MTU's unmodified `ModelPaddleOCR._estimate_colors_batch` preprocessing/per-character aggregation, its perspective crop, `Model48pxOCR` loader and `TextBlock.set_font_colors`. Paragraphs without obvious chroma use black fill and white outline directly. Native `check_color` examines original valid line crops in bounded windows, without brightness-ratio or bubble-containment requirements; gray and reversed text intentionally lose their original gray style. Other paragraphs use one valid representative line, selected with Comic Translate's existing `_line_area` rule and preference for aligned nonempty OCR; original text and geometry remain intact. These are style-policy changes, not equivalent replacements for all-line color averaging; see [ENGINE.md](ENGINE.md#排版配置). The `ocr_ar_48px.ckpt` and `alphabet-all-v7.txt` files from manga-image-translator's `beta-0.3` release are SHA-256-pinned in the same lock; the upstream GPL-3.0 source notices remain in the prepared MTU tree. One shared 48px model supplies colors only; its text never replaces the selected language recognizer. For line-aligned OCR text, the adapter feeds existing tokens through the native decoder layers and color heads in a causal full-sequence pass, bypassing character prediction and beam search. A read-only attention view preserves the incremental cross-attention XPOS query scale while calling the native attention implementation; it does not copy the attention algorithm or mutate shared modules. Unsupported or unaligned text retains native beam inference; see [ENGINE.md](ENGINE.md#资源与验证) for the reuse boundary. There is no model conversion or upstream color-source patch.

Request-local adapters keep OCR tokens isolated between pages and preserve native padding and per-character color aggregation. Returned tensors move to CPU before aggregation, avoiding per-character CUDA scalar reads. Conditioning on a different recognizer's text can change colors; this is not a claim of equivalent model outputs. Fallback beam parameters remain unchanged.

An analysis-local bounded cache reuses identical native perspective crops, RGB/BGR conversion and Paddle preprocessing only when crop identity and padding parameters match. It does not change native preprocessing or reuse differently padded long-line inputs; arrays and retained input owners are accounted for and released at analysis exit.

## RapidOCR

[RapidAI/RapidOCR](https://github.com/RapidAI/RapidOCR) 3.9.2 provides the unmodified `TextRecognizer` aspect-ratio sorting, bounded batching, resize/padding and order restoration. Its wheel and SHA-256 are pinned in `uv.lock`; Apache-2.0 notices remain in the package metadata and source. The adapter supplies the existing MTU CUDA session and decoder instead of loading RapidOCR's default models or dictionary. Before calling it, the adapter separates crops whose width at height 48 is at most 320 from longer crops; each group retains native batches of at most six and native resize/padding. No upstream recognition algorithm is copied or rewritten.

## BallonsTranslator

[dmMaze/BallonsTranslator](https://github.com/dmMaze/BallonsTranslator) supplies the unmodified `group_output` paragraph grouping and reading order, operating on MTU DBNet text lines. Its commit and archive SHA-256 are pinned in the same lock. Preparation retains `ballontranslator/`, the resources required by its library imports, `BallonsTranslator-LICENSE` and its dependency manifest under `upstream/`. No CTD checkpoint is distributed or executed. The adapter does not run the BallonsTranslator GUI or translation modules. No source extraction, rewritten grouping or upstream patch is maintained.

## Paragraph sampling and language routing

[ogkalu2/comic-translate](https://github.com/ogkalu2/comic-translate) supplies the unmodified `_line_area` rule used to select a paragraph's largest line, retaining the first line on ties. The selected line uses the same MTU perspective crop and rotation as final recognition, not Comic Translate's axis-aligned crop. Preparation retains its pinned `modules/`, `imkit/`, Apache-2.0 `LICENSE` and dependency manifests under `upstream/comic_translate/`. Its OSD model, GUI, account/credits, cloud OCR and OCR factory are not used.

[Yuff1010/Manga-Overlay-Translator](https://github.com/Yuff1010/Manga-Overlay-Translator) supplies the unmodified `detect_lang`, character-script categories and weights. Its complete OCR module and MIT notice are pinned by revision and SHA-256 under `upstream/mot/`. The adapter supplies existing paragraph crops and three batched PP-OCRv5 predictions instead of repeating detection; English replaces the Spanish candidate using the same Latin weights, and Chinese/Japanese share the CJK probe prediction. Empty/unsupported evidence is rejected before the upstream first-candidate default. No learned classifier, custom scoring, model training or conversion is maintained.

## Language-specific recognition

- Chinese / Korean / English: separate PP-OCRv5 mobile recognizers, shared between paragraph probing and final recognition. English and Chinese use the published [ogkalu/ppocr-v5-onnx](https://huggingface.co/ogkalu/ppocr-v5-onnx) ONNX weights and dictionaries under Apache-2.0; Korean files are distributed by MTU. All files are checksum-pinned. The Chinese probe also supplies Japanese routing evidence. Only selected-model representative lines padded to width 320 reuse their probe result; longer lines are recognized normally, and private results are not cached across pages.
- Japanese: [kha-white/manga-ocr](https://github.com/kha-white/manga-ocr), `manga-ocr==0.1.16`, and [manga-ocr-base](https://huggingface.co/kha-white/manga-ocr-base) at the locked revision. Original model, tokenizer, processor, model card and Apache-2.0 notice are retained. Native paragraph generation and postprocessing are unchanged.

Models load from prepared local paths only. The locked `onnxruntime-gpu` distribution supplies the CUDA inference runtime; no separate CPU `onnxruntime` distribution is installed.

PySide6-Essentials / Shiboken6 are required by upstream utility imports; their original Qt LGPL/GPL notices remain in the wheel metadata. Both are pinned to Qt 6.9.2 to match the existing PyQt6 Qt runtime. `mahotas` retains its MIT license in its distribution. Open-source license obligations remain applicable; no commercial OCR license is used.

## Runtime and data

- PyTorch and TorchVision CUDA distributions: upstream package notices and NVIDIA runtime notices are retained in wheel metadata. Qt rendering executes on the CPU.
- ONNX Runtime GPU 1.23.2 executes all three PP-OCRv5 sessions with the CUDA 12 provider; its package metadata retains Microsoft's MIT notice and bundled dependency notices.
- PyQt6 / Qt6: original package licenses remain in the distribution. DenseCRF uses the MTU author's platform wheels, with URLs and SHA-256 locked in `uv.lock`.
- PyHyphen uses bundled LibreOffice hyphenation data from the pinned Pyphen distribution. Its dictionary-specific notices are retained under `hyphenation/`; no dictionary download is performed during page processing.
- Bangers, Comic Relief Bold, Jua and Lalezar from Google Fonts; LXGW Marker Gothic from its author's repository; Noto Sans, Noto Sans CJK and the complete variable Noto Sans Arabic font for fallback: source revisions, SHA-256 and SIL Open Font License notices are listed in [assets.json](../compute-node/assets.json) and retained under `licenses/`.
- Other dependencies, including NumPy, OpenCV, Pillow, Ultralytics, timm, SciPy, NetworkX and Shapely, retain their own upstream package metadata and license files.

`mtu-assets.json` records prepared source, model, dictionary, font and notice hashes. Node startup verifies those files before importing upstream image stages. Distribution manifests include the assembled runtime and source provenance. This inventory records origins; it does not replace upstream terms.
