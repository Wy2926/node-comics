# 去字残影对照与修正（2026-09-21）

## 样本与实际执行范围

用户提供的 1072×1429 英文对白、日文拟声字混合漫画，所有原图、文字、结果与实验脚本留在 Git 忽略的 `private-test-data/production-node/`。没有调用文本供应商、翻译、嵌字或计费。

原节点为 DBNet NCNN Vulkan + manga-image-translator 48px CTC + LaMa Large ONNX DirectML FP32；检测长边 1280。LaMa 权重与上游一致，SHA-256 为 `11d30fbb3000fb2eceae318b75d9ced9229d99ae990a7f8b3ac35c8d31f2c935`。

上游参考固定于 `d5a3eee4a7b7b7754b71baa2ee82309dfff468bc`，实际执行其检测、48px CTC OCR、区域合并、CRF 掩膜细化、LaMa Large `_infer` 原始代码，使用 PyTorch CPU FP32。只跳过了会导入无关翻译供应商等组件的包初始化；没有替换数值算法。检测使用上游默认长边 2048，另做 1280 检测对照；去字分别使用 2048 与 512。这里不是上游默认的另一种 `48px` OCR，因此不能把结果推广到其所有配置。

参考环境独立于线上节点：`.venv-lama` 的 Python 3.13 / Torch 2.6.0+cpu。pydensecrf2 1.1 在 Windows 上用 Cython 3 重建；兼容层仅将 `KernelType` / `NormalizationType` 的同值枚举暴露为旧模块属性。源代码及文件散列记录于私有实验报告。

## 排除项和根因

1. **不是原对白黑色笔画没遮住。** 本样本识别框内原图灰度低于 180 的像素全部在原掩膜内；另有 47 个低于 245 的浅色像素位于原掩膜外，不能把它们算作模型生成的残影。
2. **不是 ONNX / DirectML 转换造成的可见误差。** 对真实修复块、相同 512×512 图像与二值掩膜，上游原始生成器与本地 ONNX 输出的最大绝对差为 `1.1325e-5`，平均 `9.8976e-8`（0～1 范围）。
3. **推理掩膜余量不足是本样本残影的主要可修正因素。** 原流程把紧贴文字形状的掩膜同时当作模型未知区域与最终写入范围；LaMa 会在该区域重新生成类似笔画的纹理。固定原图、裁剪窗口、缩放、权重和最终写入掩膜，仅扩大模型输入掩膜 5 个原图像素，显著减少残影。
4. **上下文和尺度也影响模型。** 原流程有 189×117 等小修复块，镜像补到 512。整页 512 推理能改善部分气泡，但扩大裁剪背景或调整缩放不能稳定解决所有区域。不能把“多给背景”或“更高分辨率”单独作为结论。
5. **拟声字漏检是独立问题。** 本地 37 行 / 15 区域；上游长边 1280 检出 38 行，2048 检出 41 行，OCR 保留 38 行 / 17 区域。上游更积极的处理也会影响复杂背景，不能用扩大去字掩膜修复漏检。

## 实现与验证

`quality.repair_page` 为模型输入单独生成 11×11 椭圆膨胀掩膜；先在原图坐标膨胀，再按原窗口裁剪缩放。`repair_region` 接受独立的 `inference_mask`。窗口选择和最终逐像素回填继续使用原掩膜，因此不扩大实际写入画面的范围。该变化进入引擎代码散列，需要节点和中心切换新引擎版本。

正式节点复验输出与固定窗口实验逐像素一致；原回填掩膜未改变，掩膜外改动为 0。该次检测／分析约 0.586 秒，去字约 1.157 秒（不含启动预热）。相关回归覆盖空掩膜、边缘位置、局部修复、原图比例、模型输入余量以及全部未授权修改像素保持不变；20 项测试通过：

私有复现脚本：`run-upstream-inpainting.py`（上游链路）、`diagnose-lama.py`（数值与上下文对照）、`fixed-mask-ablation.py`（固定窗口的掩膜对照）、`inspect-inpainting.py --fixed`（正式节点代码复验）。基线图在 `inpainting-review/`，实验在 `inpainting-diagnosis/`，修复结果在 `inpainting-fixed-review/`。单样本结论不替代彩色背景、密集手写字、透明图等的效果验收。
