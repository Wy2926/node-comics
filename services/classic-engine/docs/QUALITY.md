# 质量与性能验收 · 2026-09-19

实机：Windows、RX 6900 XT、Ryzen 7 5800X、32 GB。检测与去字继续 NCNN Vulkan，FP16 packed / storage / arithmetic 均关闭。日文 MIT OCR 保留 Vulkan 特征提取 + CPU FP32 解码；其他语言直接使用 RapidOCR PP-OCRv5 mobile ONNX CPU FP32。NVIDIA / Linux 未实机验收。

## 本轮多语言验收

- `pytest`：39 项离线回归，包括英文单词 / 断词、Unicode 标点 / 字素、韩文、目标方向、全角拉丁词、字体覆盖、旋转范围、并发像素一致性、长条覆盖 / 去重、模型缺失无网络和术语表缓存隔离。
- 真实模型合成样张：12/12 文本完全匹配。覆盖日文横 / 竖排、韩文、英文、中文、带重音拉丁文，以及英韩 18px 小字、反白和 15° 倾斜。主样本各重复 3 次，全部相同。
- 5/5 合成图片通过真实检测、识别、分组、去字、固定测试译文嵌字、PNG / JSON 落盘；长条 720×3600 的 6 条文字全部找到，跨段未重复。
- 固定测试译文不调用在线服务，不代表在线翻译质量；合成标准字体不代表自然漫画、手写标题或音效的准确率。
- 40 页本地漫画输出：414 个检测行、385 个识别行、237 个区域。与本轮改造前逐页 OCR 与有序分组文字 40/40 完全一致。
- 40 页最终输出在去字掩膜 / 排版区域之外改变像素为 0；第 15 / 25 页局部 AOT 与 CPU 参考最大通道差 1/255，掩膜外变化为 0。
- 单页 / 双页并发运行的全部 40 页 PNG 像素相同。MIT OCR 抽取 24 条原图条带与完整 FP32 ONNX 比较：24/24 文本相同，交替宽度重复两轮 24/24 logits / 颜色逐字节相同，最大 logits 误差 0.0130844。

生成示意图在 `artifacts/multilingual/preview.png`；OCR / 嵌字 / 长条详情在 `validation.json`；模型数值验证在 `artifacts/multilingual/ocr-parity/report.json`。源图和生成结果不提交 Git。

## 性能口径

40 页测试集均为 626×900，以已有翻译缓存严格离线执行；所有运行均 40 次缓存命中、0 网络请求。OCR workers=8、NCNN threads=2、PNG compression=1。

| 实现 | 在途页数 | 整章秒 | 页 / 分钟 | 平均页延迟秒 | P95 秒 |
|---|---:|---:|---:|---:|---:|
| 本轮改造前 | 2 | 17.384 | 138.06 | 0.855 | 1.247 |
| 多语言最终版 | 1 | 21.018 | 114.19 | 0.522 | 0.831 |
| 多语言最终版 | 2 | 18.288 | 131.23 | 0.903 | 1.346 |
| 同一流水线 + 旧排版 | 2 | 17.874 | 134.27 | 0.880 | 1.283 |
| 同一流水线 + 新排版 | 2 | 17.800 | 134.83 | 0.876 | 1.277 |

首轮改造（全角拉丁词修正前）双页为 137.86 页/分钟；最终复测为 131.23，同机系统 CPU 均值从最初 47.6% 升至 63.9%。随后只替换排版的两次顺序运行分别为 134.27 / 134.83 页/分钟，系统 CPU 均值 61.0% / 57.0%；旧排版运行期间还进行了约 3 秒离线模型加载检查，因此这组不是严格的独占硬件实验，不能把 0.4% 差异归功于排版。所有测量均保留，不能用最佳值代替最终测量。最终双页仍比最初测量低约 5%，无法仅凭这些运行区分代码影响与后台负载。

最终单 / 双页值见 `artifacts/multilingual-final/report.json`，排版对照值见 `artifacts/multilingual-layout-before/report.json`、`artifacts/multilingual-layout-after/report.json`。整章计时包含读取、检测、OCR、分组、去字、缓存查找、排版和写 PNG，不包含启动 / 字体覆盖预热。页延迟包含入场后的阶段等待，不包含尚未入场的排队。系统其他程序继续运行，小幅差异不能视为统计显著。

多语言处理保持原吞吐量级；当前证据不构成性能无回退保证，没有宣称整章显著提速。排版先二分测量再一次绘制，缓存字体覆盖与字形；对固定 40 页文字连续重排的隔离检查中，旧版第二轮 0.290 秒、新版 0.142 秒；冷缓存分别 0.523 / 0.772 秒。字体覆盖已移至流水线启动预热。此项只比较排版，不等于整页速度。

新增模型标准字体条带的 3 次预热后均值：英语 38.6 ms、韩语 23.2 ms、中文 24.4 ms、拉丁文 21.4 ms；同组日文 37.0 ms。每种语言只有一条简单样本，不能当作跨语言吞吐排名。

默认维持两页；要求更低单页响应时间时使用 `--pages 1`。长条漫画为了保留识别分辨率，会随分段数增加计算；没有把整章缩成低分辨率来制造加速数字。Windows GPU 指标仅是本进程最忙引擎 busy，不是全部着色器占用率。

## 之前的质量依据（历史测量）

初版 INT8 / 方形去字与此前质量模式在同机比较：检测 380→414 行，识别 327→385 行，区域 188→237；输出数量不等于准确率。第 15 / 25 页人工转录 14 个对白区域、203 个字母 / 数字 / 汉字，忽略空白与标点、统一全角拉丁且保留简繁差异，字符错误率为 6.90%→1.97%，完全正确区域 6/14→11/14。该样本开发中已看过，不是独立评估集，主要是已有中文漫画。

此前完整 414 条带与原始 FP32 ONNX 的解码一致 414/414，重复两轮逐字节一致 414/414；本轮重新检查了 24 条带。此前单页质量模式约 118.3 页/分钟、双页 138.7 页/分钟，统计口径和本轮同类。旧 INT8 / baseline 运行分支已删除，历史输出仍保留在本地 artifacts 中。

人名、简繁字形、艺术标题、弯曲音效、复杂背景修复与极窄气泡仍需人工检查。当前没有自然韩漫 / 英文漫画的标注测试集，也没有新增在线翻译评测；术语表只是可选的一致性约束。

## 气泡区域横排（2026-09-19）

针对原文竖排检测框过窄的问题，新增 `bubbles.py`：在擦字后的明亮 / 深色空白连通域中定位气泡，排除不可信背景，收缩边缘，并按距原文字框的距离分配同气泡内多个段落。原始 OCR 和擦字几何不变。横排以实际行带的空白宽度做完整单词动态分行，字号拟合后预留留白；无法满足边界或字号要求时沿用文字框排版。中日文竖排和明显倾斜文字维持已有行为。

用 `tools/replay_layout.py` 回放 `kmoe-en-ja-test/en-offline` 的全部 191 个成功页，直接复用保存的 OCR 和译文，重新运行本地检测 / 擦字。旧渲染与历史 PNG 在 191/191 页逐像素一致，排除译文和背景差异。本次没有重试原测试中失败的 3 个在线翻译页，也没有发起翻译请求。

- 1491 个文本块中，1182 个采用气泡区域排版；1089 个字号增大，采用新排版的块没有字号减小。
- 采用气泡排版的块：字号中位数 22.0 → 30.5 px；可用区域外接矩形面积与旧排版范围面积的比值中位数为 2.80（包含形状中的不可写空隙，不代表文字实际面积）。
- 全部文本块的行尾连字符 528 → 165；此项包括原译文自带连字符，不等同于纯自动断词次数。
- 单页气泡区域提取平均 32.5 ms，新排版平均 199.9 ms；这是顺序回放时的阶段耗时，不是完整 OCR / 翻译流水线吞吐量，且旧版先渲染会预热部分字体缓存。
- 抽查第 7 / 10 / 12 / 68 / 92 页输出，另以合成图检查边界、黑底气泡、内部画面、邻区不重叠、窄框救援和换行保留。自动几何检查不代替全章人工校对；原 OCR 漏字、擦字残留、开口气泡与画面背景上的窄框仍可能保持旧版效果。

逐页图像、前后排版记录和报告位于 `artifacts/kmoe-en-ja-test/en-layout/`。可对任意已有逐页 JSON 和原图目录执行 `python -m tools.replay_layout --source <原图目录> --baseline <已有输出目录> --output <新输出目录> --target en`；该工具无需翻译 API，也不重跑 OCR。

最终回归：47 项测试通过。日文 10 页旧版也逐像素复现，53 个竖排文本块的排版记录完全保持；只有 1 个横排文本块采用气泡区域。另从原图运行正式 CLI 流水线（真实中文 OCR、双页并发、英文离线缓存）10 页，全部成功、10 次缓存命中、0 次翻译请求，输出与排版回放的对应 10 页逐像素一致。主 `artifacts/kmoe-en-ja-test/index.html` 更新为前后对照，历史索引保存在 `baseline-index.html`。
