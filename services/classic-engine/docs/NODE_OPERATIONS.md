# 节点运行与恢复

发布包入口见 [Node Comics Node](../../compute-node/README.md)，源码入口见 [Classic Engine](../README.md)。中心通过[整页协议](../../../docs/COMPUTE_PROTOCOL.md)管理身份、租约和结算。

## 配置

- `gpu` 选择 NCNN Vulkan 设备，`inpaint_gpu` 选择 DirectML 设备；两者枚举不保证一致。GPU 模式禁用 CPU 回退，`gpu=-1` 为显式 CPU 诊断模式。
- `check` / `doctor` 只做本地校验；注册和心跳才能证明连接中心。模型、源码、依赖、字体与排版参数参与引擎版本，中心必须匹配实际版本。
- `max_leases` 限制本地整页租约，中心仍以 `execution_slots` 限额；`local_pages` 限制同时进行的图像计算。等待文本和交付回执仍占租约，不占计算线程。
- 本地线程、NCNN 线程与 OCR 池由节点配置；目标语言声明字体覆盖，与 OCR 来源语言独立。
- `control_ca` 可指定中心 PEM 信任文件，保留证书与主机名校验；R2 不使用该文件。节点不持有数据库、R2 或文本供应商长期密钥。

## 状态与恢复

- 一个状态目录仅运行一个节点。私有 SQLite 日志保存领取编号、分析、冻结结果及恢复信息，可能含 OCR、译文和租约令牌；限制为运行账号访问，不提交或作为通用包分发。
- 原图与抹字图受 `resident_bytes` 内存预算约束；`journal_bytes` 限制日志数据库页数，磁盘另预留 SQLite 回滚日志空间。未完成任务不手动删除日志。
- 停止时停止新领取并保留待确认交付；重启先注册对账，复用中心已持久化分析与译文。本地冻结结果重交元数据，不重新请求文本翻译。
- 原生宿主使用 Job Object 清理子进程，计算进程退出后按 1、2、4…60 秒退避恢复；网络断开由计算进程重连，避免反复加载 GPU。
- 看门狗独立检查状态新鲜度与主循环进展，超过阈值后恢复计算进程。人工停止保留恢复日志，最长等待 75 秒；正常停止不触发自启。
- `supervisor.json`、`state/status.json` 提供状态；`logs/supervisor.log`、`state/logs/node.log` 各自最多 5 份、单份 10 MiB。日志不保存令牌、正文或签名地址。

## 升级与验收

升级前排空租约、停止旧节点并保留原包与私有数据；用新包诊断，核对中心引擎版本后启动。切换到原生服务时先停止原托管方式，同一身份不能在两个宿主同时运行。恢复程序版本前检查在途任务与版本要求。

目标电脑分别验收 GPU 预热、中心注册、断网重连、进程崩溃恢复和正常停止。Windows 服务还需验证虚拟账户下的 GPU／网络权限、无人登录启动与重启恢复；桌面诊断不代替服务验收。
