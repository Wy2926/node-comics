## 运行

要求 Node.js 22.23+、npm 10+。后端默认 `http://127.0.0.1:18088`。

```powershell
cd apps/extension
npm ci
npm run dev           # http://127.0.0.1:5173，共享同一套阅读器 UI
npm run check
npm test
npm run build         # .output/chrome-mv3
npm run build:web     # dist-web
```

`npm run check` 包含严格类型、未使用变量／参数及模块边界检查；公共 UI 不反向导入 App，任务状态合并由 `src/reader/jobs.ts` 统一。详细职责与清理证据见[代码规范与模块维护](../../docs/CODE_QUALITY.md)。

Chrome / Edge 的扩展管理页开启开发者模式，选择“加载已解压的扩展程序”，打开 `.output/chrome-mv3`。安装时包含 MangaCopy 与 Copy4000 的 HTTPS 域名权限；点击工具栏后自动发现当前网页，支持刷新、过滤、选择及排序，再归入作品或插入已有副本。下载时按需授权图片域名。可直接在扩展独立阅读页导入本地图片、无 DRM MOBI、CBZ/ZIP、CBR/RAR 或 PDF。

2026-09-15 网页采集弹框与导入流程已更新，操作、过滤阈值和隔离浏览器复现见[网页图片发现与加入漫画](../../docs/WEB_IMAGE_IMPORT.md)。

2026-09-15 本地导入改为预检清单与逐份队列：提前标出重复、补齐原图，支持选择／移除、收起进度、暂停／继续及失败重试。交互、运行边界与验收见[本地漫画导入流程](../../docs/LOCAL_IMPORT_FLOW.md)。

`.npmrc` 使用 `legacy-peer-deps` 避免 npm 10 对 Vitest 可选浏览器 peer 递归解析时的 `edgesOut` 异常。实际使用 WXT 0.21.4、React 19、Vite 7 和 Vitest 5；测试与生产构建分别验证。开发工具的 `web-ext → addons-linter → image-size 2.0.2` 有尚无 npm 修复版的高危 ICNS/JXL/HEIF 解析公告，未进入最终扩展包；`npm audit --omit=dev` 单独检查运行依赖。不使用不兼容的旧 web-ext 版本掩盖审计结果。

## 本地数据和任务

2026-09-14 已实现[通用作品管理与 MangaCopy](../../docs/COMIC_LIBRARY_IMPLEMENTATION.md)。书架按作品管理章节、卷册、内容版本、收录关系与可读副本，MangaCopy 支持详情页整目录／范围导入和断点采集。全新 `node-comics-library` 数据库不读取或迁移旧书架，旧存储与扁平 Chapter 逻辑已移除。

2026-09-14 已扩展压缩包与 PDF，并增加 `Page.imageSha256` 和匹配请求 `image_sha256`，用于不同包装中相同原图的免上传恢复。完整[格式边界、缓存规则与依赖许可](../../docs/IMPORT_FORMATS_AND_CACHE.md)；[本次验证](../../docs/evidence/import-cache-validation.md)。必须配套更新 API；以下早期验收数量保留其日期，不替代本次验收。

- 图片 Blob 与书架在 IndexedDB；对象 URL 只用于当前挂载窗口，卸载即释放。连续模式最多挂载当前页附近 5 张图片，并按 3200 万像素预算收缩窗口。并排对照保持各自图片比例。
- 阅读位置保存为页面 ID 与页内相对位置。未登录可直接阅读本地原图；登录后打开／导入漫画仅发送文件页标识查找已有翻译，不上传全卷。开始翻译时仅上传尚无有效服务器原图的选定页，确认报价后才创建任务。
- MOBI 按记录切片读取，不执行书内 HTML；使用现有图像尺寸避免全卷解码。无 DRM MOBI6/PalmDOC 支持范围、KF8/HUFF/DRM 等限制由导入器显式报错。GIF 仅取首帧转 PNG，其他图片保持原始字节。
- 身份、资产和任务由服务 origin 与用户 ID 双重隔离。更换服务地址需显式保存，地址改变会退出登录。切换身份后，队列中尚未发送的旧请求停止，已发请求的迟到结果不会写入新账户页面。供应商 Key 永远不在前端。
- 提交前持久化报价与幂等键；收到结果并保存任务 ID 后才清除待核实记录。刷新后显示原确认入口并沿用同一个 key；上游结果未知不自动重发。主动生成新版本使用专门的 rerun 接口。
- 自动翻译首次默认关闭。确认模式、每页点数及持续使用账户额度后，本机按账户、服务、模式、语言记住开启选择，刷新、返回阅读和换漫画后自动继续；手动关闭也会记住。手动翻译本页不关闭自动翻译；按当前页和后 10 页跟随阅读，提前量可设 0–50 页，本次翻译总页数不设上限。快速跳页后未提交的窗口失效，已有结果和进行中任务不重复提交。关闭开关或离开阅读器后阻止新任务提交；服务器已接收的任务独立继续执行。准备阶段的网络故障、限流、短暂服务错误和明确拒绝的过期报价、配置变化、额度不足每 15 秒重试；未确定是否成功的提交保留同一幂等记录，核实前不新增任务。暂停保留开关并显示原因，价格变化需确认；同价内部配置变化按新报价继续。
- MangaCopy／Copy4000 按目录与图片容器 data-src 发现，核对总页数后逐页下载；xkcd / Gunnerkrigg 仅标识当前一期或单页。通用适配器发现当前 DOM 与懒加载地址，默认过滤小图与横幅，可手动恢复，不声称完整章节。所选清单可成为独立副本，也可插入已有副本；图片获取失败保留原因，重试可补齐原图。
- 授权码 + PKCE 支持在后端提供正式 OIDC 配置时启用；开发登录仅在后端 `dev_auth` 开启时显示。实际身份服务与商店安装仍需部署环境验收。

本地示例为原创《星光书店》原图，没有预制或伪造译图。图片格式校验不等同于翻译质量验收，实际 AI 翻译须保留原图与最终输出对照。

历史版本的构建、权限检查、依赖审计与 ZIP 校验和见 [前端验证记录](../../docs/evidence/frontend-validation.md)，该记录不代表本次变更的验收结果。

## 跨设备翻译恢复

- `Page.fileHash` 是原始文件字节的 SHA-256 小写十六进制摘要；`pageIndex` 从 0 开始，属于文件的原始页序。排序、删除页面和自然文件名排序均不重新编号。
- MOBI 的所有页共享整文件摘要，索引取解析正文图片引用的原始顺序（同一图片重复引用也保留不同页索引）。GIF 转 PNG 不改变原始 MOBI 身份。最大文件仍为 512 MB；本地增量 SHA-256 每次只读取至多 1 MiB，跨块仅保留摘要状态，块间让出主线程；没有新增依赖或整文件 `arrayBuffer()`。
- 独立图片每张使用自己的原始文件摘要 + `0`；网页获取成功的图片按实际取得的图片字节摘要 + `0`。文件名、来源 URL 和阅读顺序不参与匹配。获取失败的网页页暂时没有文件身份，保留具体失败原因。新书架不读取旧数据；没有旧标识恢复分支。
- 上传 `POST /v1/images` 的 multipart 除 `image` 外，可成对提供 `file_hash`、`page_index`；前端新导入页始终携带两项。`POST /v1/file-pages/match` 请求 `{pages:[{file_hash,page_index}],mode,target_language}`，每批 1–100 项；返回同序 `{items:[{file_hash,page_index,asset,jobs}]}`。整卷拆批，重复身份合并查找；响应身份／次序不符时不绑定页面。
- 自动恢复只在打开漫画、登录、切换翻译模式／语言时触发，且只查询 capabilities 中已启用的模式。任务状态更新不会重复扫描全卷。阅读器的“恢复已有翻译”可手动重试；仅复用同一账户、服务、有效配置、语言和模式下的记录。原图失效时由后端返回未命中。
- 匹配到可用成功版本、`no_text`、排队、运行中或 `outcome_unknown` 时，普通翻译准备不会为该页再上传、报价或提交。后端返回的有效原图即使没有译图，也可避免重新上传。匹配失败不会被当成未命中；其余已核实页面仍可准备，失败页保留可重试原因。
- 恢复得到的任务接入原有轮询，译图按请求并发下载并校验可解码后入库。不同页面失败独立，更新合并到最新页面，不改动页 ID、原图尺寸、排序与阅读锚点。匹配开始后的新上传资产不会被旧匹配结果覆盖；版本按创建时间优先排序，适应配置更新后的版本号重置。历史本地译图版本继续保留，但不能替代当前服务器配置的匹配判断。
- “主动生成新版本”把旧任务 ID、有效输入资产和目标页一起持久化，报价和 `rerun` 使用同一输入。跨书相同图片匹配到其他输入资产时，仍保留当前页的文件身份与上传资产映射，不通过普通批次误命中缓存。待核实提交始终优先使用原 pending key，自动匹配不会清除或重建该记录。
- 批次返回任务按持久化的选中页 ID／报价资产关联，优先使用可选 `Job.requested_asset_id`，缺省才使用 `input_asset_id`。这样双设备／多本书复用同一任务时，不依赖提交期间可能改变的页面当前资产；原任务的真实输入资产保持不变。

## 两种并发设置

| 设置 | 保存位置 | 生效范围 |
| --- | --- | --- |
| 本机请求并发 | 本机设置 `requestConcurrency`，默认 2，整数 1–10 | 此阅读器的上传、文件匹配、状态和译图下载等请求共用限流池；页面读取／上传准备也有并发边界。降低值时已发请求完成后再按新值派发。 |
| 账户翻译队列并发 | 当前登录账户的后端配置，显示当前生效值、默认值和上限 | 后端按用户轮转派发任务，实际执行还受服务容量限制，与本机请求并发独立。 |

登录后打开偏好设置会 `GET /v1/me/queue` 读取 `concurrency/effective_concurrency/default_concurrency/max_concurrency/queued/dispatched/running`。点击“保存账户设置”才发送 `PUT /v1/me/queue {concurrency:1..10|null}`；`null` 恢复服务端默认值。修改本机请求并发不会发送该 PUT，也不改变自动翻译的提前页数或开启状态。
