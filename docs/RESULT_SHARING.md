# 译图共享与匹配

2026-09-20：面向全新空库的实现，初始基线 `payments_0001`。无旧表迁移、缓存别名任务回填或旧逻辑回退；未切换已有服务或部署。

## 存储与权限

- `jobs` 只记录实际受理的翻译。显式重译建立新任务，保留旧结果；缓存命中不创建任务、执行阶段、分钟准入事件或额度账本，也不进入 `/v1/jobs` 与管理后台任务列表。
- `translation_results` 每次真实生成完成登记一条，包括无字结果；主键为生成任务 ID，记录内容匹配键与真实生成完成时间。重复完成通知不重复登记，核实成功的重绘也在同一交付事务登记。
- `result_accesses` 每个用户、每个生成版本最多一条，保存自己的图片授权引用、版本序号及变更游标。没有供应商配置、执行状态、阶段与扣费记录。本人已持有有效结果时直接复用，反复请求只增加契约要求的操作回执。
- `translation_operations` 通过互斥外键指向真实任务或结果授权；同一操作键仍严格校验请求签名。用户、文件和访问权限保持隔离，绝不把生成者的私有任务 ID 当作请求者的授权。
- 图片对象仍按内容全局去重；本人的同内容、同类型、同父图有效 Asset 授权也复用。用户删除只撤销其授权，共享对象不删除。其他用户已有有效授权时，该版本仍可作为共享来源；所有来源都失效时不能命中。

同一内容被 N 个新用户复用，新增的是 N 条必要的结果授权及各自的图片授权，而非 N 份完整任务。结果条数随真实生成次数增长，不随复用次数增长。再次明确请求有效共享版本可更新本人已失效的结果授权；原已删除 Asset 不复活，旧访问地址仍失效。

## 匹配和锁

1. 使用 `SHA256(原图字节)`、模式、语言和当前有效配置版本生成匹配键。仍为字节级精确匹配。
2. 获取全局调度锁之前查询共享候选，同一请求内相同键只查一次；已存在操作回执跳过候选查询。候选只是提示，不写授权、不扣额。
3. `translation_results(cache_key, generated_at, id)` 索引按真实生成时间查找版本；SQL `EXISTS` 验证是否存在有效来源，不把所有用户授权展开后排序，不将全部历史候选加载进 Python。返回至多一个版本和一个有效来源。
4. 按既定 scheduler → user 顺序取得锁，重查操作回执及本人结果，按主键复核候选的匹配键、原图、译图和删除／到期状态。候选失效或锁外未命中时，再在锁内作有界查询，避免漏掉刚完成的结果而重复扣量。当前配置变化时旧配置候选不会命中。
5. 命中后原子写授权和回执；未命中才建立真实任务、分钟事件和页数预占。读取原图时先通过用户＋内容索引查询本人授权，再查任意有效共享原图，避免对热门图片的全部授权按用户排序。

匹配、状态与签名查询不访问 R2；下载与生成仍走原有存储契约。全局锁仍保护准入、共享授权写入、优先级与游标提交顺序，本次缩短匹配部分的持锁时间，不宣称整个缓存请求完全无锁。

## 阅读接口

阅读器仍接收统一的逐页 `job` 响应结构，缓存项的 `id` 是当前用户的结果授权 ID，`cache_hit=true`、`quota_pages=0`、`settlement=free`。这是只读投影，不是数据库任务；批量状态、文件匹配、操作恢复、变更订阅、结果反馈和从该版本重新翻译均支持它。任务列表只显示真实任务。

已有本人结果优先复用；其他用户匹配全局结果时按真实生成时间选择。新增授权或重放操作不会刷新共享版本的生成时间，因而旧译图不会因近期被复用而挤掉新译图。

## 验证

从仓库根目录执行；环境全部位于 Docker，宿主机不需要虚拟环境：

```powershell
$env:RUN_POSTGRES_CONCURRENCY='1'
docker compose -p node-comics-tests -f deploy/compose.tests.yaml up --build --abort-on-container-exit --exit-code-from tests
docker compose -p node-comics-tests -f deploy/compose.tests.yaml down
```

新增检查包括多用户多次命中后的行数、任务历史为空、私有 ID 隔离、文件恢复／反馈／重译、删除生成者后其他授权继续共享、撤销与重新授权的唯一性、真实生成时间排序，以及候选查询先于全局锁、锁外候选失效后的复核。所有供应商调用使用隔离模拟，不涉及付费模型。
