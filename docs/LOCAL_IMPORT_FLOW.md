# 本地漫画导入流程

2026-09-15 已实现并在隔离浏览器中验证。入口仍为书架／阅读器的本地文件选择和书架拖放。

## 用户流程

1. **选择与检查**：选择文件后立即打开文件清单，逐项显示检查进度。根据文件内容检查重复，文件名变化不影响判定。现有漫画原图完整时显示“已存在 · 跳过”，可以直接打开；缺少原图时显示“待补齐原图”。全部重复时明确说明漫画已在书架，无需点击开始导入。
2. **整理批量范围**：支持追加文件、全选／取消选择、移除条目及按待处理／已存在／失败筛选。每次选择的多张图片按自然文件名顺序组成一份副本，可展开查看顺序；漫画文件各自独立。默认归入同一作品，也可选每份文件分别新建作品。已有内容保留原归属。
3. **逐份导入**：面板顶部显示批量进度与当前文件，文件行显示页数进度。当前文件自动进入清单可视区域。可以收起为右下角进度卡，继续使用书架和阅读器；不会自动跳离当前阅读位置。
4. **控制与结果**：可在当前文件完成后暂停、继续，或停止尚未开始的文件。已完成内容立即入库。某个文件失败不影响其他文件；支持单项／全部失败项重试。结果分别列出新增、补齐原图、已有跳过、失败和取消，保留具体原因与阅读入口。

移除清单中的条目只移除本次导入记录，不删除书架漫画。选择“完成”清空本次清单。追加文件须等待当前检查／导入结束；暂停中的批次先继续或停止剩余任务。

## 实现边界

- 队列属于当前阅读器页面，文件与原图留在本机，不创建翻译任务。收起面板继续处理；刷新或关闭页面会丢失未完成清单，重新选文件即可利用内容检查跳过已完成项。暂停／停止在文件之间生效，不强行中断正在解析的文件。
- 预检不解码整份漫画：压缩包与 MOBI 使用整文件 SHA-256；图片组使用排序后的图片摘要；PDF 沿用原有渲染配置指纹，检查现存的对应渲染副本。PDF 仍保留实际页图摘要，配置或渲染结果变化不会覆盖旧版本。
- 单次清单复用已计算的漫画文件摘要，避免正式解析时再次扫描整文件。现有格式、大小与像素限制保持有效；内容损坏、加密与解码错误仍在具体解析阶段报告，预检通过不代表文件已经解析成功。
- 每份文件单独保存和提交；提交前再次核对书架，批内重复成功一份后跳过后续相同内容。最终沿用 IndexedDB 原子事务去重，防止其他标签页同时导入造成重复副本。失败文件清理未引用的中间图片，已成功提交的文件保留。
- 补齐原图沿用已有页面 ID、译图关联、内容归属和阅读位置。原图是否完整由本地存储实际可用性判断。

## 验证与复现

在 `apps/extension` 运行：

```powershell
npm test
npm run check
npm run build
npm run build:web
npm run dev -- --port 5176
```

在仓库根目录生成原创格式样本并运行验收。Python 样本脚本需要 Pillow、ReportLab；浏览器脚本使用已安装的 Playwright 与 Chromium，可通过 `PLAYWRIGHT_MODULE`、`TEST_CHROMIUM` 指定运行时。

```powershell
python scripts/generate_import_fixtures.py
node scripts/verify_local_import.mjs
$env:TEST_EXTENSION='1'
node scripts/verify_local_import.mjs
Remove-Item Env:TEST_EXTENSION
```

验收使用全新浏览器上下文／扩展配置目录，不操作日常漫画库。长篇样本由脚本根据原创图片生成；后端请求被隔离，未登录、未调用供应商。
