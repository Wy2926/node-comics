# 插件图像增强

清晰度优化是独立的客户端图像处理能力，默认关闭。插件只实现外部服务协议，不运行模型、不新增后端引擎或任务接口，也不使用 NodeLane 翻译额度。外部服务自身的费用、部署与模型许可由用户管理。

## 使用与处理顺序

在「设置 → 增强渠道」添加服务地址、图像类型、放大倍率和降噪参数，选择一个配置后开启「清晰度优化」。可保存多个服务配置，同一时间只选择一个；阅读设置提供开关、当前渠道及配置入口。保存配置只校验字段和浏览器访问权限，不发送测试图片，不表示已连接成功。

- 图片阅读器、EPUB 内嵌图片：选择译图时，按 **翻译 → 完整结果 → 增强** 处理；已确认无文字且交付 `original` 的结果直接增强正在显示的原图，不等待不存在的覆盖文件，也不复制一份译图缓存。选择原图时可直接增强原图。翻译尚未完成、失败或结果失效时不抢先增强原图，不拼接增强底图与旧覆盖层。EPUB 正文不参与处理。
- 图片阅读器优先直读增强缓存；未命中时，实际显示窗口独立读取完整译图／原图，增强在后台排队或恢复原任务，完成后原位替换。增强等待和失败不阻塞已有图片，也不显示为「正在读取译图」；该提示只代表图片本身的读取。
- 网页原位翻译：只增强已完成结果，包括无文字终态的原图。已有增强缓存直接显示；需要新处理时保留完整译图／原图，再替换增强结果。「恢复原图」仍恢复网页本身的原图，增强重试独立于翻译重试。原图恢复复核已有内容摘要，变化时停止，不将新内容当作旧翻译结果发送增强。
- 并排对照的左侧始终是未增强的原图。关闭增强恢复完整译图／原图；增强不改变源图身份、翻译结果身份、阅读尺寸、页锚点或 EPUB 文档结构。
- 单页增强失败保留当前图片，提供独立重试，不重新翻译、不阻塞其他明确可执行的页面。连接中断、超时或宿主消失时，远端可能仍在处理；同一服务暂停新的自动提交，用户确认后手动重试。
- 图片阅读器与 EPUB 共用排队、处理中和失败提示；EPUB 原图模式也可重试增强，预取页失败在进入当前页后仍保留。渠道重命名、缓存预算调整不撤销显示中的图片；增强开关或参数变化不重置翻译任务。
- 目前不接入划图截图、文件导出、官网或整本离线任务。上色未实现，也不预置空渠道、后端任务或可配置流水线。

## 协议与适配边界

入口为 [`image-processing/`](../apps/extension/src/image-processing/)。`registry.ts` 装配具体适配器；`ProcessingAdapter` 声明配置字段、规范化和 HTTP 图片请求。界面与运行器不按渠道 ID 编写协议分支。新增服务协议时实现独立适配器并注册，不更改翻译 `Job`、语言、模式或额度体系。

首个适配器是 [nunif / waifu2x HTTP 服务](https://github.com/nagadomi/nunif/blob/master/waifu2x/docs/web.md)，对应 [服务协议实现](https://github.com/nagadomi/nunif/blob/master/waifu2x/web/server.py)：

| 请求 | 约定 |
| --- | --- |
| 地址 | 配置服务根路径，向其下 `POST api`，支持反向代理前缀 |
| 图片 | multipart `file`，直接传入完整父图片 Blob，不再次压缩、缩放或拆图 |
| 类型 | `style=art / art_scan / photo` |
| 倍率 | `scale=-1 / 1 / 2`，分别对应不放大／1.6×／2× |
| 降噪 | `noise=-1 / 0 / 1 / 2 / 3` |
| 输出 | `format=0` 请求 PNG；验证响应状态、图片 MIME 与实际解码 |

适配器不假设模型、GPU 或服务端算法。此协议没有可核实的任务查询、远端取消或进度百分比，插件只显示排队、处理中、完成或失败。服务的文件大小限制由部署方配置；HTTP 413 明确提示，插件不隐式降低清晰度后重试。当前原生 nunif 协议不接额外登录、令牌或公共演示站验证码。

只接受无凭据、查询参数和片段的 HTTP(S) 服务地址。请求不携带源站 Cookie、Referer 或 NodeLane 凭据；配置的服务及其重定向目标必须可信。响应正文、图片和私密地址不进入默认日志。此实现未复制第三方代码、模型或权重，仅根据公开协议独立实现客户端。

## 执行、缓存与性能

翻译和增强复用协议无关的 [`image-transfer/`](../apps/extension/src/image-transfer/) HTTP 执行、回执及长请求宿主；增强不复用翻译的 `DirectImageRuntime`、操作记录或状态机。

- 增强与翻译共用 [`reading-window.ts`](../apps/extension/src/reading-window.ts) 的窗口上限、首屏延迟和滚动合并规则，时序以[阅读触发](READING_TRANSLATION_CONTRACT.md#7-阅读触发与优先级)为准。图片阅读器两者使用同一阅读目标：当前及后三页，随当前页滚动最多五页；EPUB 两者使用当前及后三张内嵌图片；原位增强使用真实阅读窗口、最多五张，不跟随未完成翻译批次移位。译图模式仅在对应页完整翻译就绪后增强，不因等待某页而把窗口向后递补。
- 图片增强由独立的有限窗口持有，只发布增强结果和已有执行状态；普通图片读取与显示仍由图片组件负责，不接收增强输入回调，避免重复解码父图。单页翻页同样预处理后续页，只解码实际显示窗口内的图片。翻译与增强不共享任务、重试或结算状态。每个增强服务端点仍跨标签页串行执行，不因窗口大小或配置版本变化扩张并发。离开窗口、隐藏阅读器或关闭增强会取消尚未提交的等待；已发出的 POST 只停止等待展示，不宣称远端已取消。
- 统一先按 `所属 owner + 父图身份 + profile.id + profile.revision` 的摘要查索引。原图身份使用现有 `page:` 引用（条目、内容、页面、渲染版本），译图使用 `result:` 引用（翻译作用域、任务 UUID、结果版本）。缓存命中不读取、合成、解码或计算父图摘要，只解码增强图片；命中前后仍复核来源、内容代次、账号和结果访问权限。
- 译图身份登记与像素读取分离。阅读窗口只登记有限的结果读取器，真正显示时才下载／合成；阅读器、EPUB、网页原位共用惰性增强入口，不再先加载父图才能查增强缓存。网页本身或 EPUB 容器的正常原图加载不属于增强依赖，并排对照左侧仍需原图。
- 索引未命中且确需新请求时，取得服务串行槽后才加载一次完整父图，按 1 MiB 分块计算可取消 SHA-256，再以索引身份和输入摘要构造内容键。发送前持久化记录、UUID 和回执；运行中记录只观察原 UUID，终态回执可直接恢复落盘，无须父图。失败、结果不明或已完成但缓存丢失，均须手动重试，不自动补发。
- HTTP 执行端负责完成增强缓存写入、保存处理终态与释放回执字节，不依赖当前阅读页面仍在等待；阅读端恢复调用同一个幂等收尾入口。执行端异常留下的终态回执仍可恢复。明确终态会落到服务槽中，不因回执过期误阻塞服务。
- 独立字节缓存默认 10 GiB，可选择 128／512 MiB、1／10 GiB，保留已有有效预算。设置页显示实际缓存字节占用，读取已有统计，不扫描图片；10 GiB 是上限，不预先占用磁盘。复用现有 `ByteCache` 的 LRU、总预算和迟到写入隔离。存储压力可以淘汰增强图片；磁盘准入失败时，已有的有限传输回执仍可向当前读取者交付一次结果，消费后释放字节，不增加另一套增强缓存。
- 手动清理默认勾选「同时清理处理记录」，按批删除已结束记录及其回执；再次查看可重新增强。进行中的记录与服务执行保护保留，阻止重复提交和迟到图片写回。取消勾选或自动淘汰时保留处理记录，再次调用服务必须手动重试。结果不明的服务仍须手动重试确认，清理记录不解除这一保护。
- 移除漫画／来源会清除所属增强缓存与回执；移除增强渠道只清理该配置的派生数据，并阻止迟到结果写回，不使其他配置在途结果失效。删除已明确完成的回执前保留服务终态，不把正常清理误判为连接中断。更换翻译账户或结果后不展示旧身份的增强图片。
- 首次增强增加一次完整图片上传、一次结果下载及必要的图片验证解码，倍率增加会显著提高像素内存；热缓存只增加增强图读取，进入显示窗口才做展示解码。最多五张压缩结果 Blob 留在阅读窗口；增强输入仍取得服务串行槽后才加载，完成后释放，显示所需父图复用普通图片读取与缓存，不扩大父图预取范围。较原两张窗口，最多多处理三张图片，换取翻页前准备完成；不扩大 DOM／展示解码窗口，不把整本图片预先送入增强。关闭时没有增强请求、摘要计算或模型操作。
- 渠道名称、缓存预算、界面刷新标记不参与缓存键；仅清理缓存不会伪装成新身份并自动重算。旧增强记录在数据库结构升级时直接丢弃，不迁移、不兼容旧查询方式；旧字节仍受同一缓存预算／清理操作约束，不作为新索引命中依据。

## 验证

`apps/extension` 下执行 `npm run check`、`npm test`、`npm run build`。单元测试覆盖共享窗口时序、五页上限、未挂载页预处理、快速跳页取消、翻译完成后补入但不移动锚点、父图不可用时直接命中、缓存命中授权、分块取消、离页落盘与回执过期、协议字段、默认关闭、跨调用去重、清理后显式重试、禁用、结果不明、配置移除隔离及 EPUB／原位阅读窗口边界。

启动插件 Vite `--port 5176` 后，在仓库根目录执行 `node scripts/verify_image_enhancement.mjs`（`PLAYWRIGHT_MODULE`、`CHROMIUM_PATH` 用法见[脚本入口](../scripts/README.md)）。复用隔离渠道夹具，校验真实图片上传摘要与完整译图完全相同、同翻译窗口、单页模式后三页预处理与滚动补位、服务串行、挂起增强时重开／翻页先显示译图、热缓存不读父图、开关缓存恢复、失败保留、手动重试不重译、并排对照、阅读位置和窄屏表单，截图及测量写入忽略的 `artifacts/image-enhancement/`。

浏览器夹具使用合成服务响应，证明交互与协议载荷，不证明真实 nunif 部署、模型效果或 GPU 性能。实际效果与吞吐需要用用户选定的服务和代表性漫画另行验收。

EPUB 使用现有 `tests/epub-reader.browser.mjs` 与隔离 5198 夹具，覆盖原图增强失败、预取失败滚入当前页、独立重试及 CFI 保持；启动方式见[脚本入口](../scripts/README.md)。

`node scripts/verify_translation_channel_host.mjs` 使用正式 MV3 构建的隔离副本与回环 HTTP 服务，覆盖后台重启后的直传回执恢复、原位翻译后增强、增强请求不携带 MTU 凭据及跨上下文缓存开关恢复。仍不调用真实引擎。
