# 节点配置

图像节点使用整页 v3 协议，经中心读取临时原图并提交覆盖文件。部署使用 [Windows 节点包](../services/compute-node/README.md)或 [Linux NVIDIA 镜像](../services/compute-node/linux/README.md)，开发使用 [classic-engine](../services/classic-engine/README.md)。

## 中心与本地的职责

中心按 `execution_slots` 限制节点持有的整页租约数。下载、等待文本、等待交付均占租约，但不占图像计算线程。缩容与停用只限制新领取；已接页面继续按领取时保存的处理时限完成。

后台日常只需设置最大在途页数与启停；超时参数折叠在高级设置中。表单和 JSON 使用同一 schema，拒绝未知字段：

| 字段 | 默认值与用途 |
| --- | --- |
| `schema_version` | 1 |
| `execution_slots` | 1，范围 1–32；按节点实测吞吐与资源预算调整 |
| `poll_seconds` | 20 秒，范围 1–30；通知丢失时的领取兜底 |
| `heartbeat_seconds` | 10 秒，不超过租约时长的三分之一 |
| `request_seconds` | 30 秒，范围 1–120 |
| `page_seconds` | 900 秒，整页处理时限 |
| `text_wait_seconds` | 600 秒，分析提交后等待文本的上限 |
| `delivery_seconds` | 120 秒，首次交付后的重试窗口 |

节点先预热，使用后台预建的独立凭据注册；注册不能扩容或解除停用。管理员修改配置后，新领取按新版本校验；节点通过长轮询、心跳和领取响应获取配置，迟到旧版本不会覆盖新版本。节点凭据轮换后旧凭据立即失效。全部接口与配套升级要求见 [协议实施](COMPUTE_PROTOCOL.md)。

## 节点本地配置

复制 [node.example.json](../services/classic-engine/node.example.json) 为私有文件。必填 `protocol_version:3`、中心 HTTPS `control_url`、`node_id`、`node_token` 和 `resource_id`；不配置对象存储 origin 或凭据。可用 `control_ca` 指定私有中心 CA，仍验证服务器证书和主机名；节点凭据只发送到配置中的中心。

中心不修改本地模型、线程或缓存：

| 字段 | 默认值与用途 |
| --- | --- |
| `max_leases` | 8；与中心执行位取较小值 |
| `local_pages` | 2；检测／OCR 与抹字共用的计算池大小 |
| `render_workers` | `auto`；独立嵌字编码槽位与渲染进程数，可显式指定 1–max_leases |
| `download_workers` | 4；下载池及独立分析提交池大小 |
| `delivery_workers` | 4；最终交付与停止确认池大小 |
| `resident_bytes` | 1 GiB；在途页面缓冲、渲染 IPC 与蒙版缓存预算，不含模型、GPU 工作空间和进程常驻内存 |
| `engine` | 模型位置、CUDA 设备、算子线程、检测与修复尺寸、字体 |

`engine.threads` 与 `render_workers` 默认为 `auto`，只在启动时解析。有效 CPU 取逻辑 CPU 数、进程亲和性、Linux 当前 cgroup 及可见祖先的 CPU 时间配额／cpuset 的交集限制；配额可为小数，整数分配预算 `C` 向下取整、至少为 1。无法完整读取约束时保守回退到 1 并告警；命名空间隐藏的祖先限制无法探测。Windows 使用进程亲和性，不把宿主机核数当成可用数。

设 `P=local_pages`、分析原生线程数 `T`、渲染位数 `R`。两项均自动时，`T=max(1, C//(P+1))`，再令剩余预算 `B=max(1, C-P*T)`、`R=min(max_leases, B)`；多进程每个渲染器的原生线程数为 `max(1, B//R)`。显式 `R`、自动 `T` 时，先用 `T=max(1, C//(P+R))` 再分配剩余预算。显式整数原样保留，不静默限缩；单渲染位与分析同进程，原生线程同为 `T`。最小并发或显式配置超过有效 CPU 时告警。这是避免盲目超分配的启动策略，不是跨机器最优吞吐保证；操作系统、网络和其他进程也使用 CPU。`check`、启动日志与状态文件显示完整检测依据及分配结果，修改硬件限额后需排空重启。既有私有配置不会自动改写成 `auto`。

检测／OCR、抹字与嵌字编码使用独立有界调度池。多渲染位在预热的 CPU-only spawn 子进程中完成 Qt 排版、差分、裁剪／分块、无损 WebP 编码与输出校验，直接返回覆盖文件和小型结果描述，不回传整页 RGB。GPU 模型仍只在主进程常驻；单渲染位与共享内存不足时在主进程执行同一页处理函数。计算池优先推进已就绪的抹字，避免一批待分析页面拖住已有页面的交付；同阶段按就绪时间调度，不向执行器堆积无界任务。嵌字不占 `local_pages`，但仍属于同一页租约，保持阶段顺序、一次交付与原有恢复语义。等待文本、下载、覆盖文件上传或中心回执时不占计算线程。新接单数量同时受中心执行位、本地 `max_leases`、每批最多 4 页、下载队列空位和 `resident_bytes` 余量限制；已领取但尚未取得内存的页面也计入预算。设置 12 个执行位只允许最多 12 个未交付页面，不会直接提高本地计算并发。

两个池共享 CPU、内存与页缓冲预算，不保证多核线性加速。嵌字积压仍占在途页数和预留内存，达到上限后停止补领／取图；停止或失败需等待工作退出后再释放共享段及缓存，不中断其他页面。渲染进程异常退出时先排空旧进程池，本页失败，后续页面可重新建立进程池；正常关闭拒绝新任务并等待全部缓冲回收，主进程异常退出时子进程跟随退出。MTU 适配器分别保护 DBNet、OCR 和 MangaLens 的共享调用；已预热的 FP32 LaMa 只读推理允许计算池内并发，不同模型与 CPU 蒙版细化可交错执行。保持框架默认 CUDA 流，不保证 GPU 内核同时运行。Qt 字体／词典缓存按进程隔离，同进程上游调用仍串行。增加计算或嵌字路数前应实测吞吐、P95 延迟与峰值内存。

每页下载前按 `22 × 像素数 + 3 × 输入字节数 + 24 MiB` 预留工作缓冲，其中 `6 × 像素数` 为跨阶段蒙版额度：分析时保留原始文字／检测／气泡蒙版，有气泡时继续保留该额度，供抹字后换为内缩蒙版、int32 标签及有界统计表。抹字完成后按实际数组 `nbytes` 收缩，不再同时保留原始三张蒙版；无气泡时分析完成即可释放多余额度。分析局部裁图与预处理缓存最多占一张 RGB 原图大小，计入其余工作缓冲、分析退出即清除。所有页缓存只读、仅随该页存活，等待译文时也计入预算；恢复检查点先校验格式，再一次性解码检查像素。PNG/base64 仍用于持久化与协议，不作为同一进程内阶段间的唯一数据形式。尺寸和字节数取自中心租约描述，不再用固定图片上限估算。新页尺寸在领取后才确定，所以仍可能有少量已领取页等待内存；领取门控不能替代这个限制。内存不足时暂停取图，租约和处理期限仍有效；单页超出预算直接失败。

嵌字取得槽位时，先为这一批就绪页面按顺序预留共享输入段，再分配可选缓存。无预备标签时 IPC 为 `8 × 像素数`，有标签时为 `12 × 像素数 + 统计表字节数`，包含原图、背景、气泡内缩蒙版、alpha 及标签／统计表；不足的页面本地执行，不等待内存。剩余预算按整张 uint8 蒙版大小在这些页面间轮流分配，最多 `像素数 × 非空译文相交的唯一气泡集合数`，不按段落数重复预留、不分配无法装下一张蒙版的零头。连通区域标签属于已预留的页工作数据，不会因可选缓存刚够标签大小而挤掉全部参考蒙版。没有有效译文时不预留 IPC 或参考缓存，没有气泡时不预留参考缓存；未缓存参考项仅在相关连通区域范围内重算。后续页面不抢占正在使用的缓存，因此不同到达时序、紧预算仍可能触发本地回退；不是全局最优调度保证。Linux 还须成功预留 `/dev/shm` 后备页，分配失败仅回退本地并告警，不把未知工作进程错误当作内存不足。工作退出后关闭、删除共享段并归还 IPC 与参考蒙版预算；失败和停止须等使用者排空后释放页内蒙版，不等待终态回执。

长图已协商分块输出时，Qt 保持整页排版，只对最终像素并行差分、编码和校验。进程渲染池的 CPU 配额由上述启动策略确定，排版使用本进程配额，输出阶段非阻塞借用当前空闲配额并在结束时归还；新到页面可能等待借出配额归还。线程数还受实际区块数限制，不超出整个渲染池的配额。没有进程池或 IPC 不足时串行输出，不增加另一套 CPU 设置。自动 CPU 分配本身仍不按实时负载重规划。

冻结覆盖文件后清除计算缓冲，把该页预占缩到 `2 × 覆盖文件字节数 + 24 MiB`，覆盖二进制日志读取、传输和元数据。结果 PUT 在独立交付池中并发，分析、完成描述与结果 BLOB 保存在私有 SQLite 恢复数据库，终态回执后删除，SQLite 自动回收空闲页。恢复数据库没有按页数设置的容量上限，也不按磁盘余量控制领取；未确认交付不能按年龄删除。模型、字体和有效算法配置共同决定引擎版本，线程／进程预算不改变结果身份；节点无独立翻译 CLI 或 PNG 压缩配置。

下载阶段完成、冻结缩减内存、终态释放和配置变化都可立即补领；非空领取后仍有空间时连续发起下一批，空领取才等待 `poll_seconds` 或新提示。节点新请求最多申请 4 页；协议仍接受 1–32 的容量请求，中心对新分配最多发放 4 页。待确认的领取请求保持原编号、配置版本与数量，重试不重新计算其内容，中心返回保存的完整回执。

heartbeat、claim、updates 各有独立通道，各最多一个在途请求。`updates` 保持最多 20 秒的 HTTP 长轮询并直接带回译文、停止和终态变化，不续租；heartbeat 独立定时续租。无关全局通知继续等待，租约集合或真实可领取状态变化可以结束等待以重建请求快照；细节见[通知协议](COMPUTE_PROTOCOL.md#分阶段流水线与通知)。持久状态重查与周期领取负责断线补偿，无需新增 WebSocket。

分发与进程恢复由 [Node Comics Node](../services/compute-node/README.md) 原生宿主管理，使用随包运行时、模型和固定字体；支持初始化、离线诊断、原生 Windows 服务、独立进程看门狗和人工停机。诊断日志在 10 MiB 时轮转，保留当前文件及最多 5 份备份，与保存未确认任务的恢复数据库分开管理。私有数据可放在独立目录；新电脑需要独立身份，搬移身份必须先停止原宿主并排空租约。协议或引擎检查点不兼容时，先用原程序排空，再初始化匹配的新配置，不复制不兼容的恢复数据库。网络重试、进程恢复与服务账户环境分别验收，不能用进程存活推断中心在线。

文本与上传恢复各有独立控制资源池。其执行位是所有工作进程共享的数据库容量，扩大池容量不会绕过供应商限制或用户分钟准入限制。

## 目标语言与节点能力

产品的常规翻译目标项来自 [backend/app/languages.py](../backend/app/languages.py)：`zh-Hans`、`zh-Hant`、`ja`、`en`、`ko`、`fr`、`es`、`pt-BR`、`de`、`it`、`ru`、`pl`、`uk`、`tr`、`vi`、`id`，共 16 项。

节点注册时报告 `supported_languages`，节点启动时依据字体覆盖自动检测目标语言，中心直接使用注册能力；不配置目标语言白名单或默认引擎指纹。来源 OCR 按段分流到 PP-OCRv5 或 Manga OCR，不要求客户端传来源语言；具体组合见[引擎支持范围](../services/classic-engine/ENGINE.md#支持范围)。未知或该模式未开放的目标语言返回 `LANGUAGE_UNSUPPORTED`。

仓库包含 [classic-engine](../services/classic-engine/README.md) 源码、模型清单和测试；模型权重与字体需另行准备。产品允许选择某目标语言，不代表已有可用节点，也不代表 OCR 能可靠识别该源语言。接入引擎需要自行验证源语言 OCR、目标字体、换行、缺字和排版边界，并准确报告能力。交互与恢复见[计算协议](COMPUTE_PROTOCOL.md)。

`engine.gpu` 是非负 NVIDIA CUDA 设备索引，Windows／Linux 使用同一路径。引擎选项仅有 `models`、`gpu`、`threads`、`detect_size`、`inpainting_size`、`font`、`keep_lang`；未知参数直接拒绝。默认检测边长 1280，修复边长 512（可选 768／1024）。`threads` 同时约束 PyTorch、ORT 辅助算子和 OpenCV 的 CPU 线程，不增加租约并发或 CUDA 推理批次；多核节点应结合容器 CPU 配额、分析耗时与并发嵌字负载实测调整。`keep_lang` 默认为 `null`；只有限定源语言的节点／对照测试才配置 ISO 639-1 语言码（如 `zh`），不匹配的识别段落保持原图。用所选设备完成预热、真实 DBNet／OCR／LaMa 与 Qt 嵌字后再登记能力；GPU 初始化失败不降级 CPU。
