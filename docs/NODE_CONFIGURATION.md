# 节点配置

当前图像节点统一使用整页 v2 协议，入口为 [classic-engine](../services/classic-engine/README.md)。旧阶段接口、compute-agent 与中心下发引擎线程／缓存覆盖已删除，不接收旧配置字段。切换使用空数据库和新节点日志；原图与译图的 R2 对象保留。

## 中心与本地的职责

中心按 `execution_slots` 限制节点持有的整页租约数。下载、等待文本、等待交付均占租约，但不占图像计算线程。缩容与停用只限制新领取；已接页面继续按领取时保存的处理时限完成。

中心配置如下，后台表单和 JSON 使用同一 schema，拒绝未知字段：

| 字段 | 默认值与用途 |
| --- | --- |
| `schema_version` | 1 |
| `execution_slots` | 1，范围 1–32；本机建议 8 |
| `poll_seconds` | 20 秒，范围 1–30；通知丢失时的领取兜底 |
| `heartbeat_seconds` | 10 秒，不超过租约时长的三分之一 |
| `request_seconds` | 30 秒，范围 1–120 |
| `page_seconds` | 900 秒，整页处理时限 |
| `text_wait_seconds` | 600 秒，分析提交后等待文本的上限 |
| `delivery_seconds` | 120 秒，首次交付后的重试窗口 |
| `allowed_languages` | 默认中简／中繁／日／英／韩，与节点声明能力取交集 |

节点先预热，使用后台预建的独立凭据注册；注册不能扩容或解除停用。管理员修改配置后，新领取按新版本校验；节点通过心跳获取配置。节点凭据轮换后旧凭据立即失效。全部接口与恢复规则见 [协议实施](COMPUTE_V2_IMPLEMENTATION.md)。

## 节点本地配置

复制 [node.example.json](../services/classic-engine/node.example.json) 为私有文件。中心不修改本地模型、线程或缓存：

| 字段 | 默认值与用途 |
| --- | --- |
| `max_leases` | 8；与中心执行位取较小值 |
| `local_pages` | 2；同时运行的有限图像计算步骤数 |
| `download_workers` | 4；下载池及独立分析提交池大小 |
| `delivery_workers` | 4；最终交付与停止确认池大小 |
| `resident_bytes` | 1 GiB；在途页面缓冲预算，不含模型及 GPU 工作空间 |
| `journal_bytes` | 512 MiB；每个租约至少预留 64 MiB 日志空间 |
| `engine` | 模型位置、Vulkan 设备、OCR 来源语言、算法线程和排版参数 |

本地分阶段调度交替推进准备与嵌字；等待文本、下载、R2 上传或中心回执时不占计算线程；R2 PUT 在独立交付池中并发，渲染完成即继续下一页。内存不足时暂停新页面取图，租约和处理期限仍有效；单页超出预算直接失败。原图和抹字图只留有界内存；分析与冻结结果保存在有界私有日志，收到终态后释放。模型、字体和算法配置共同决定引擎版本。

节点保持一个最多 20 秒的变更长轮询；通知到达立即触发批量心跳获取译文并尝试补领，续租心跳独立运行。通知仅唤醒，实际状态仍从数据库读取；断线重连和周期检查负责补偿，不依赖通知持久化。

文本、重绘、上传恢复各有独立控制资源池。其执行位是所有工作进程共享的数据库容量，扩大池容量不会绕过供应商限制或用户在途限制。
