# 官网语言选择与支付返回设计

2026-09-20。本文件是待实现的语言方案；本轮已单独修复插件订阅按钮的刷新竞争，不把语言方案记为已经上线。

## 当前问题

- 官网由 URL 选择语言，简体中文没有前缀，其余使用 `/zh-tw/`、`/en/`、`/ja/`、`/ko/`。当前没有语言偏好 Cookie 或 localStorage，手动切换只改变 URL。
- Stripe 成功地址固定 `/payment/success/`，所以首次总显示简体中文；该页面的五语链接也没有记忆功能。
- 静态文件缓存只缓存资源，不代表记住用户语言。成功页当前为 `private, no-store`、`noindex, nofollow`。
- 插件 `MembershipCard` 原先在每次 focus/visibilitychange 时发起 Stripe 对账，并与打开订阅门户共用 busy/working，导致按钮间歇变为“处理中”且点击被忽略。与网站语言或浏览器缓存无关。

## 目标与优先级

首次从无语言入口访问时，匹配浏览器偏好列表；没有支持的语言时使用英语。用户主动切换以后，无语言入口优先使用其保存的选择。明确带语言的链接始终展示链接指定的语言，不能被 Cookie 或浏览器偏好强行跳走。

| 场景 | 决策 |
| --- | --- |
| 无语言入口，有有效手动偏好 | 使用手动偏好 |
| 无语言入口，无手动偏好 | 按浏览器语言偏好依次匹配 |
| 偏好缺失、全部不支持或格式非法 | 英语 |
| 直接访问 `/ja/pricing/` 等语言地址 | 日语；不跳走、不覆写保存偏好 |
| 在语言菜单主动选择 | 保存该选择，跳到同一内容的对应语言地址 |
| 登录、退出或切换账户 | 保留本浏览器的网站语言偏好 |

“以修改后的为准”作用于后续自动选择和默认入口；明确语言链接表达本次访问的选择。这样既记得用户偏好，也允许打开别人分享的其他语言页面。

## 路由

建议为所有语言使用明确前缀：`/zh-cn/`、`/zh-tw/`、`/en/`、`/ja/`、`/ko/`。根 `/` 作为无语言入口，不再兼任简体中文首页。

| 路由 | 行为 |
| --- | --- |
| `/` | 语言协商后临时重定向至 `/<locale>/` |
| `/<locale>/pricing/`、文章等 | 稳定 200，服务端静态输出该语言；不做语言协商 |
| `/payment/success/` | 独立的无语言支付返回入口，语言协商后临时重定向 |
| `/<locale>/payment/success/` | 固定语言成功页，免登录、禁止索引与缓存 |
| `/account/` | 无语言账户入口，协商后跳到明确语言账户页 |
| `/auth/callback/` | 保留已登记的 OIDC 精确回调；先完成身份校验，再返回已保存的站内目标，不参与语言重定向 |

Stripe 继续使用同源固定 `/payment/success/`，不把偏好或身份信息拼进支付 URL，也无需为每种语言维护 Stripe 产品。取消结账、门户返回仍进入账户入口，不显示支付成功。

当前无前缀的简体中文文章、定价等地址若已有外部入口，切换路由时做确定性的单次 301 到 `/zh-cn/...`，与 Cookie、请求头、IP 无关；内部链接、canonical、hreflang、sitemap 同步替换。根路径和支付返回路径承担新的中立入口职责，不作中文 301。此项是网页地址调整，不涉及账户、数据库或支付任务迁移。

## 浏览器语言匹配

服务端解析 `Accept-Language` 的质量权重与顺序，忽略 `q=0`、非法标签和不支持项，最多检查有限数量的标签。对未指定权重的标签使用默认权重；权重相同保留顺序。不按 IP 推断语言，不区分爬虫 User-Agent。

| 浏览器标签 | 网站语言 |
| --- | --- |
| `zh-Hant` 及其地区变体，或无明确脚本的 `zh-TW` / `zh-HK` / `zh-MO` | 繁体中文 |
| `zh-Hans` 及其地区变体，或无明确脚本的其他 `zh` | 简体中文 |
| `en` / `en-US` / `en-GB` 等 | 英语 |
| `ja` / `ja-JP` | 日语 |
| `ko` / `ko-KR` | 韩语 |
| `de-DE, fr-FR`、空列表、通配符无有效候选 | 英语 |

明确脚本优先于地区，例如 `zh-Hans-HK` 使用简体。浏览器第一语言不支持时继续匹配后面的支持项，例如 `de-DE, ja;q=0.9` 选择日语。检测到的默认结果不写成永久偏好，否则以后修改浏览器语言会失效。

## 偏好存储

采用一个仅保存白名单语言值的第一方 Cookie：`nc-site-locale`，`Path=/; Max-Age=31536000; SameSite=Lax; Secure`。不设置 Domain，仅对当前官网主机有效，不与身份服务共享；它不包含用户编号或令牌。

语言菜单保留普通 `<a href>`，点击时同步保存 Cookie，随后进行原生导航；不依赖异步请求才能切换。只有主动点击才写入偏好；访问别人分享的语言链接不自动覆盖。浏览器禁用 Cookie 时仍能通过链接正常浏览，只是不跨会话记忆。清除站点数据后重新按浏览器匹配；隐身窗口、其他浏览器和不同临时 CF 域名各自独立。

服务器读取 Cookie 可以在输出 HTML 前确定入口跳转，避免先闪现中文再切换语言，也不需要再维护一份 localStorage 副本。所有已打开页面保持当前 URL，不因另一标签页修改偏好而突然切换；下一次进入中立入口时使用最新偏好。

插件 UI 语言与官网 Cookie 属于不同存储范围，不能暗中跨 origin 读取。用户当前要求的网站偏好用于官网及支付结果页；插件自身的语言设置维持独立。后续如果需要跨设备、跨产品统一偏好，应另行明确账户级设置。

## 搜索引擎与缓存

自动协商只发生在中立入口。所有明确语言内容页对普通访客和爬虫输出相同、完整、单一语言的 HTML，允许直接访问，不依赖 JavaScript 生成正文，也不按 Cookie 替换相同 URL 的正文。

- 每个公开语言页使用自身 canonical；五种语言互相提供 `hreflang`，且包含自己。首页 `x-default` 指向中立根 `/`；其他内容的 `x-default` 指向对应英语版本。
- sitemap 列出五种语言的公开规范 URL；账户、身份回调、支付结果不列入。成功页和账户页使用 HTML robots 与 `X-Robots-Tag: noindex, nofollow`；允许爬虫取得页面以识别 noindex，不依赖 robots.txt 禁止抓取来实现去索引。
- 中立入口使用 302，`Cache-Control: private, no-store`，`Vary: Accept-Language, Cookie`。CF/CDN 缓存规则显式排除这些入口以及账户、支付页，防止把某个用户的语言跳转缓存给所有人。
- 公开明确语言页不因语言 Cookie 变化而改变响应，不添加无意义的 `Vary: Cookie`；继续按 URL 缓存。带哈希静态资源沿用长期 immutable 缓存。
- 语言菜单始终为可抓取的普通链接。没有请求头的爬虫按同一默认规则得到英语，仍能通过 hreflang、sitemap 和链接发现全部语言；不实施爬虫专属内容或绕过策略。

依据：Google 建议不同语言使用独立 URL，并避免在明确的语言版本之间按推测偏好强制跳转；其爬虫默认可能不发送 Accept-Language。本设计据此把协商限制在中立入口，完整版本保持稳定。[多语言网站](https://developers.google.com/search/docs/specialty/international/managing-multi-regional-sites)、[语言自适应页面抓取](https://developers.google.com/search/docs/specialty/international/locale-adaptive-pages)。此设计改善可抓取性，不承诺收录或排名。

## 插件订阅按钮修复

本轮实现将状态分成“读取/刷新权益”与“打开 Stripe”。背景刷新保留当前会员卡及主按钮；只有用户发起打开操作，主按钮才显示“处理中”。重复打开由独立锁合并。

普通 focus/visibilitychange 只读服务端已持久化订阅状态，30 秒内合并，不每次调用 Stripe。手动刷新，或本页实际打开 Stripe 后返回时，才补充一次服务端对账。Webhooks 和 maintenance 仍承担后台结算与恢复。同步错误与打开错误分别维护，旧同步结果不得覆盖切换账户后的状态。

## 语言方案验收清单

实施时覆盖：无 Cookie 的五种语言与不支持语言；Accept-Language 多项/权重/非法值；繁简脚本和地区优先级；手动选择后重进首页、重新支付、退出登录；直接访问不同语言链接；Cookie 禁用；身份回调不跳转；普通访问与无请求头爬虫访问；CDN 不交叉缓存语言；所有公开语言页的 canonical/hreflang/sitemap；支付失败或取消不会进入成功页。

预计改动范围：服务端中立入口、前端统一语言匹配与菜单偏好写入、简体中文路径、站内链接/SEO 生成、对应测试与部署缓存规则。该语言方案尚未实施；本轮交付的是明确设计和独立的订阅按钮修复。
