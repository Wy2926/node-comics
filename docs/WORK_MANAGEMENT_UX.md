# 作品管理与导入交互恢复

日期：2026-09-23。本文记录旧版交互审查与本轮恢复范围；具体实现和验证状态以当前代码及对应验收记录为准，不将计划列为已通过功能。

## 模型与目标

继续使用 [来源与缓存架构](COMIC_SOURCE_ARCHITECTURE.md) 的 `Work → ReadingUnit → Document`：作品组织内容，阅读单元表示章节、卷或未分类内容，文档表示可阅读的来源版本。恢复旧版中便于整理作品、选择版本和继续阅读的交互，不恢复被替代的全库状态或出版关系模型。

旧版 `PublicationContents`、`LibraryEditor`、`CopyCards` 的分类列表、展开详情、编辑反馈与版本卡片具有复用价值。重构后过度简化的作品详情丢失了分类、筛选、归属修正、封面与首选版本等入口；导入中“新建作品”藏在选项内，现有作品选择又受当前书架分页限制。本轮在新模型上补齐这些操作。

## 本轮恢复范围

| 优先级 | 交互 | 新模型中的落点 |
| --- | --- | --- |
| P0 | 导入明确选择新建作品或已有作品；已有作品支持全库搜索 | 独立作品查询，不复用书架当前页作为完整候选集 |
| P0 | 区分作品名称、阅读单元名称、内容类型与角色；清楚说明批量文件如何归属 | `Work.title`、`ReadingUnit.title/kind/role`；已有单元继承其元数据，避免显示修改后无效的字段 |
| P0 | 点击某版本打开该版本；继续阅读恢复真实位置 | 显式文档选择优先于单元首选；继续阅读先恢复有效的阅读位置，再采用可读首选与回退 |
| P1 | 按章节、卷及其他类型查看；按角色、已读状态筛选；搜索和排序 | 阅读单元分类与持久阅读状态，不引入独立出版物关系图 |
| P1 | 编辑作品、阅读单元和文档；纠正同作品内的文档归属 | 应用层提供受校验命令；文档的来源、修订与页面身份保持稳定 |
| P1 | 设置作品封面、阅读单元首选文档，展示语言与版本说明 | `Work.cover`、`ReadingUnit.preferredDocumentId`、文档元数据；删除与归属修正同步维护引用 |
| P1 | 批量标记已读／未读，展示最近阅读并提供继续阅读 | 明确持久完成状态；更新时间不能代替已读状态 |
| P1 | 统一“导入漫画”入口，在弹框选择文件来源 | 本地与文件来源共享归属流程，保留导入进度、暂停、重试与失败原因 |

网站适配导入仍由网页内嵌按钮触发；插件导入弹框不增加“网站来源”按钮。文件来源通过通用驱动契约接入，作品管理和归属表单不包含 Google 等特定来源的授权逻辑。

书架与章节／卷册卡片使用右键菜单，不常驻省略号按钮；支持菜单键、Shift+F10 和触屏长按。详情卡片使用 3:4 纵向封面，将内容类型、性质、阅读状态、页数、版本、来源、语言与版本说明放在封面标签上，不显示文件格式标签。未读、阅读中和已读使用独立图标、文字与配色。下方仅保留固定标题空间和阅读按钮。封面和标题仍进入版本详情；编辑、已读切换及版本管理由右键菜单提供。版本窗口只常驻阅读与首选操作，其余操作折叠。批量选择、批量操作和顺序调整只在用户主动开启对应模式后出现。

书架取消分页和页码行，作品总量以账户头像同款描边徽章放在“我的漫画”旁，宽度随位数展开；排序位于工具栏最右侧。首页、详情与详情编辑弹框复用统一自定义下拉框，菜单避让视口边缘和滚动条区域。搜索与排序基于全库轻量作品索引；卡片使用虚拟行窗口，只挂载可视行与上下各两行，邻近卡片才加载单元、版本、来源和封面，离开窗口后释放。返回书架恢复筛选、排序与滚动位置。索引不包含作品简介、文档树、页面描述符或图片字节。

来源标签由文件来源驱动或网站适配器提供名称；通用网页使用具体域名，不将作品名称或云盘账号名称作为来源。按来源身份去重，同一来源追加多个版本只计一个来源：单来源显示名称，多来源显示“{数量} 个来源”，悬停可查看名称列表。书架与作品概览统计整部作品，详情卡片统计该阅读单元的全部版本；统计不能被书架单元／版本的元数据分页截断，不读取远端图片或源文件字节。

作品详情顶部在宽屏中左右分区：左侧封面与资料，来源、阅读单元、版本、已读数采用图标、名称和数值分层的统计块；右侧阅读操作及三点菜单，菜单包含“添加内容”“编辑作品”和“移除作品”。最近阅读展示真实阅读时间，未阅读时显示“还没阅读”。窄屏将操作区换到资料下方并保持右对齐。卡片更新与验证见[卡片与菜单验收](validation/CARD_MENUS_2026_09_23.md)。

批量导入必须明确展示“同一作品下分别创建阅读单元”与“每个文件新建作品”的区别。多张散图组成一个图集时仍按一个文档处理。选择已有阅读单元意味着添加该单元的另一个文档版本；修改单元类型或角色应使用明确的编辑操作。

## 应用层约束

界面只提交用户意图，由应用服务维护所属关系、首选版本、封面和阅读位置。不得从表单直接改 IndexedDB，也不得为恢复旧控件重新引入全库读写的 `editLibrary`。

文档归属修正限定同一作品内的阅读单元。显式阅读某个文档时，不能被该单元的首选文档覆盖。继续阅读、已读状态和排序应使用各自真实字段：阅读位置负责恢复页面，完成状态负责筛选，最近阅读时间负责排序。

封面和首选文档必须引用当前作品或单元内的有效数据；删除或移动文档后处理失效引用。编辑标题、语言、版本说明、归属等管理元数据，不应触发原图重导入、来源重新授权或改写冻结修订。

## 不随本轮恢复的旧耦合

- 旧 `LibraryState`、`Copy` 及整库对象修改接口，不作为新版管理界面的存储后门。
- 旧出版物关系、跨作品页段覆盖、任意重排文件内部页段等关系图，不因恢复分类列表而自动重建；如需此类能力，另行明确需求和数据模型。
- “已持有全部原图字节才可阅读”的前提不恢复；远端来源继续按需读取，索引和缓存职责保持分离。
- 原图缓存清理与译图版本删除不合并，来源断开与删除作品也不等价。
- Google 专属账号、令牌、快照字段不进入作品管理、阅读器或翻译公共逻辑；实现与注册处保留必要的来源配置。

## 验证边界

本轮应验证新建作品与全库查找、批量归属、分类与筛选、编辑保存及取消、同作品归属修正、封面与首选、已读持久化，以及显式版本和继续阅读的选择顺序。目标浏览器应检查宽窄布局、空结果、失败提示和阅读位置恢复。

自动化测试、模拟来源与真实浏览器操作分别记录；既有来源接入或旧版截图通过，不能替代本轮作品管理交互验收。最终测试数量、浏览器范围和截图见[本轮验收记录](validation/WORK_MANAGEMENT_2026_09_23.md)。
