# 客户端 UI 重设计提案 · 清透漫游

日期：2026-09-14。状态：**整体方向已获确认并完成本轮客户端及服务端改造。** 本文保留设计依据和候选细节，实际功能、接口与验证边界见[实现说明](UI_IMPLEMENTATION.md)。

本轮细化：用户已明确自动翻译与查看、同模式只展示最新效果、反馈与重新翻译、缩略图列表目录。具体交互以[翻译交互细化](TRANSLATION_UX_PROPOSAL.md)为准；其他页面仍沿用本提案。

依据：[产品设计](PRODUCT_DESIGN.md)、现有 `App.tsx` / `Reader.tsx` / `ServerJobs.tsx` / `styles.css` 与服务端任务、额度接口。本文中的书名、封面构成和数字均为设计示意，不代表实际账户数据、漫画目录或正式价格。此提案不将候选设计升级为已确认产品要求。

## 1. 风格文字描述

**清透、舒展、有漫画杂志感的专业二次元阅读空间。** 用大封面、克制的版式和鲜明的文字层级建立气质。页面采用冷白或中性浅灰底，深墨色文字，一种有辨识度的主题强调色。二次元感主要来自漫画封面、轻盈的章节编号和少量星形品牌细节；主题色集中在选中项、阅读进度和主要操作。

“大气”落实为宽阔的内容区、清晰的大标题、充足的卡片间距和稳定对齐；“清新”落实为干净的背景、轻边界、局部柔和的强调色；“专业”落实为完整的状态语言、明确的操作反馈和一致的数据口径。连续使用时优先看到自己的漫画和阅读进度。

建议默认主题为 **晴空蓝**，另提供樱花粉、薄荷绿、鸢尾紫。亮暗外观与主题强调色分别设置。漫画图片保留原本色彩，阅读背景独立设置为纸白、浅灰或夜色。

### 当前痛点与设计响应

| 现状证据 | 影响 | 新设计 |
| --- | --- | --- |
| 样式中有 93 处 10–13px 字号声明，其中 10px 有 39 处；数量包含各模块和媒体查询，不等于同时出现的元素数 | 标签、状态、说明阅读费力 | 正文和操作 16px，重要书名 20px，辅助信息通常 14px；空间不足先换行或减少字段 |
| 默认次要文字 `#979BAA`，多处浅粉、浅蓝、浅灰叠用 | 信息边界弱，状态与装饰争夺注意力 | 深墨正文、明确的次级灰；主题色、业务状态色、画作颜色各自承担固定职责 |
| 书架先显示营销横幅和功能介绍 | 已有漫画需要向下找 | 顶部直接显示标题、导入入口、紧凑的继续阅读区和漫画卡片 |
| 阅读器沿用全局侧栏、顶栏，另有多排工具和翻译侧栏 | 漫画画幅被挤压 | 阅读器成为独立全宽空间，目录和翻译工具默认收起 |
| 本地记录按单页逐条列出，另设服务器任务档案 | 同一本漫画被拆散，信息重复 | 一个记录入口，按漫画与批次分组，详情查看逐页状态 |
| 额度页主要呈现预占、结算、释放等逐笔事件 | 很难回答一段时间实际用了多少 | 用量统计作为主页面，流水作为可展开明细 |

## 2. 信息架构与整体布局

桌面采用紧凑的横向主导航：**我的漫画 / 翻译记录 / 用量统计**。右侧保留外观与设置、账户入口。管理员功能继续受权限限制，收到账户菜单下，不占普通用户主导航。

列表、记录、统计共享导航，页面内容最大宽度建议 1440px，左右边距 32–56px。阅读器不继承该导航，使用全宽画布。低于 760px 时主导航换到下一行；更窄屏幕以单列内容和按钮换行保持字号。

```text
┌ Node Comics ─ 我的漫画 ─ 翻译记录 ─ 用量统计 ───── 外观 / 账户 ┐
│ 我的漫画                                         ＋ 导入漫画 │
│ [继续阅读封面] 海风来信 · 第 01 卷       第 42 / 180 页  继续读 │
│ 全部漫画                     最近阅读 ↓    [封面网格 | 横向卡片] │
│ [     大封面     ] [     大封面     ] [     大封面     ]       │
│  书名              书名              书名                     │
│  位置 / 页数        位置 / 页数        位置 / 页数               │
│  翻译状态           翻译状态           翻译状态                  │
└────────────────────────────────────────────────────────────┘
```

空书架显示一个清晰的导入区、支持的图片格式及未加密 MOBI、一个原创示例入口。无登录也可打开原图。离线状态只在需要联网的操作附近提示。

## 3. 漫画列表：两种大卡片排列

### A. 封面网格 · 默认

- 竖向封面比例建议 3:4，卡片宽约 220–280px；1440px 内容区可排 4–5 列，按最小宽度自动减列。320–390px 手机采用一列，保留大封面和易读标题。
- 书名独立放在封面下方，20px，最多两行；较长书名可展开完整标题。封面点击和卡片内明确的阅读按钮都能打开漫画。
- 默认信息只有书名、已读位置、翻译摘要，例如“读至 42 / 180 页”“中文译图 24 页”。翻译数量必须绑定所选语言及模式，或明确写成“有译图的页面 24 页”。
- 阅读进度使用轻量横线及数字，未读显示“尚未开始”。异常文字保留，例如“原图需重新导入”；不能用颜色圆点代替原因。
- 移除、改名、更换封面收进单个更多菜单。批量选择在进入管理模式后出现。

### B. 横向大卡片 · 扫读与管理

每行一本，行高约 144–164px。左侧 88–104px 宽竖封面，中间是大书名、来源和位置，右侧是阅读按钮与更多菜单。进度和翻译状态分行呈现，避免挤成一串小字。窄屏把操作放到文字下方。

```text
┌─────────┬─────────────────────────────────────┬─────────────┐
│         │ 海风来信 · 第 01 卷                 │  继续阅读   │
│  大封面 │ 本地导入 · 180 页                   │     ⋯       │
│         │ 读至第 42 页   ━━━━━                 │             │
│         │ 常规 · 中文译图 24 页               │             │
└─────────┴─────────────────────────────────────┴─────────────┘
```

排列和排序保存在本机，两种排列共享数据、当前位置与筛选结果。继续阅读仅占一条横向卡片，不另设大幅营销区。最近阅读不等于整卷缓存完整；清理原图后仍显示位置并提供重新导入。

## 4. 阅读器：安静的画布，可发现的工具

### 默认阅读

顶部一条约 64px 的轻工具条：返回漫画列表、书名、当前模式与语言、阅读设置。画面上方用一条稳定的小标签说明原图或译图及任务状态；底部是缩略图目录、上一页／页码／下一页、翻译本页与自动翻译。全屏入口置于阅读设置。漫画是绝对视觉主体。

```text
┌ 返回漫画列表       海风来信 · 第 01 卷      常规 · 中文 ▾     ┐
│                  原图 · 正在翻译                           │
│                                                            │
│                 ┌──────────────────────┐                   │
│                 │                      │                   │
│                 │       漫画画面       │                   │
│                 │                      │                   │
│                 │                      │                   │
│                 └──────────────────────┘                   │
│                                                            │
│ 缩略图目录       ‹  42 / 180  ›     翻译本页    自动翻译 [关] │
└────────────────────────────────────────────────────────────┘
```

默认控制条可见，第一次使用无需猜操作。用户主动开启沉浸模式后，控制条可自动收起；移动指针至边缘、轻点画布空白区或按 Esc 唤回。键盘焦点位于控件、正在操作面板或错误需要处理时不自动隐藏。对话框中的 Esc 先关闭对话框，再恢复阅读控制。

### 按需展开

| 入口 | 内容 | 展示方式 |
| --- | --- | --- |
| 目录 | 单列缩略图列表、页码、当前位置与当前模式／语言的状态；范围选择在翻译流程中启用 | 左侧抽屉，默认关闭 |
| 当前模式与语言 | 选择常规／AI 重绘及目标语言，只展示对应最新效果 | 小弹层，无历史版本选择器 |
| 阅读设置 | 连续／单页、方向、适宽／适窗、缩放、全屏、背景、沉浸模式 | 单个设置面板 |
| 翻译本页 | 按当前偏好获取有效报价，按钮明确点数后可提交 | 基本操作直接在底栏完成；批量范围按需展开 |
| 自动翻译 | 本次页数与点数上限、完成后自动显示偏好 | 开启时一次确认；暂停一次点击 |
| 译图有问题 | 问题类型、选填说明、免费提交反馈；独立的重新翻译入口与报价 | 当前译图旁的轻面板 |
| 翻译详情 | 当前批次与逐页问题、剩余任务、边读边译预算 | 在同一翻译抽屉中切换内容 |

辅助面板同一时间最多打开一个，浮于画布上方；不改变漫画布局宽度。目录可以独立开关，展开时保护原阅读锚点。窄屏允许面板占据主要区域，关闭后恢复原锚点。保存图片、批量范围、反馈与重新翻译放在对应详情中。

启动翻译必须先看到明确报价，例如“24 页，预计预占 48 测试点数”；已有译图直接切换不会启动新任务。边读边译默认关闭，开启时说明当前页及后 2 页、本次最多页数与点数预算。

### 柔和而明确的反馈

原则是 **减少提示面积与重复次数，保留足够的字重和对比度**。

| 状态 | 默认显示 | 操作与行为 |
| --- | --- | --- |
| 正在读取原图 | 在当前图片的预留区域显示“正在读取这一页” | 保留原始比例，不跳动；附近页面仍可阅读 |
| 翻译进行中 | 页边一条 14px 提示“正在翻译，先读原图”，批次以已完成页数计数 | 展开详情才显示具体阶段；单页不编造百分比 |
| 当前页译图可用 | 已自动展示则持续标明“译图 · 模式 · 语言”；仍看原图则标明“译图已就绪 · 查看” | 默认自动显示，用户主动原图偏好优先；切换保持页内位置 |
| 部分完成 | “部分文字保留原文” | 查看详情；实际释放额度时显示“本页未扣点数” |
| 失败 | 页边显示“本页翻译失败 · 查看原因” | 其他页继续；详情给出具体恢复动作 |
| 结果待核实 | “结果待核实 · 查看进度” | 不提供普通的一键重试，不自动重发图片请求 |
| 原图缺失 | 图片占位中显示“原图需要重新导入” | 重新导入／返回来源；不宣称已采集完整章节 |
| 结果过期或删除 | 当前页保留原图，“译图已过期” | 可恢复本地有效副本；重新翻译走新报价 |
| 离线 | 本地原图正常读；翻译入口旁显示“连接后可翻译” | 不在每页重复弹出全局错误 |

非阻断成功提示约 3–4 秒自动消失，原图／译图身份标识持续保留；失败与待核实持续到用户查看或状态恢复。必要操作不藏在一闪而过的提示里。状态带文字和图形，不能只靠红绿识别。

## 5. 翻译记录：先读得懂，再展开细节

主列表按 **漫画／阅读清单 × 批次 × 模式 × 目标语言** 组织，日期作为分组标题。卡片第一行是 20px 书名与整体状态；第二行是范围、模式、语言与提交时间；第三行展示完成、等待、失败数量及已结算／预占点数。

```text
今天
┌ [缩略图] 海风来信 · 第 01 卷                 正在翻译       ┐
│          第 01–24 页 · 常规翻译 → 简体中文                  │
│          已完成 18 / 24 页 · 4 页等待 · 2 页处理中          │
│          已结算 36 点 · 预占 12 点      查看详情   继续阅读  │
└────────────────────────────────────────────────────────────┘
```

- 详情展开逐页行：页码、状态、简短原因、已结算或预占、上下文动作。阅读入口只打开当前模式／语言的最新效果；不提供旧版本切换。原始任务 ID 和错误码在“技术详情”中按需查看。
- 同一批次全部任务失败、部分失败、仍在处理中和结果待核实分别表述；“进行中”不包含需要核实的任务。
- `succeeded` 仍需看 `quality_flags` 与 `result_available`；部分保留原文、已过期和正常可读的译图不能都显示为同一种“已完成”。
- 每页消耗从结算事实得出，不能直接把任务 `cost` 一律显示为已扣费。
- 本地与服务端任务按任务 ID 去重，统一入口显示。服务端未关联书架的条目写“未关联本机漫画”，可按文件标识重新关联；不能因缺书名而丢掉记录。
- 一个任务可能因复用出现在多个请求／批次中，展示关系按回执保留，计数与结算按业务任务去重。
- 完成后的主操作为“阅读译图”；失败为“查看原因”；待核实为“查看进度”。重新生成只在详情里出现，并重新说明费用。
- 过期历史仍保留记录，结果按钮改成明确的不可用原因，不把过期结果当成可交付图片。

## 6. 用量统计：流水的统计化呈现

主导航名称建议“用量统计”，页面内使用“点数明细”承接原流水。“账户”只负责身份及额度摘要。

布局为：时间范围 → 本期已结算点数 / 交付版本数 → 每日用量趋势与模式分布 → 点数明细。当前可用及预占作为独立的即时账户摘要，明确不受历史时间范围影响。首版使用测试点数单位，不展示人民币、充值或订阅入口。

```text
用量统计                                      最近 7 天 ▾
当前可用 1,488 点 · 预占 24 点（实时）

本期已结算                     本期已交付
320 点                         160 个页面版本

每日已结算用量                  按翻译方式
  ▂  ▃  ▂  ▅  ▃  ▄  ▅          常规翻译     260 点
  08 09 10 11 12 13 14          AI 重绘       60 点

点数明细                                        展开逐笔事件
时间            漫画 / 页码              类型          点数
今天 14:40      海风来信 · 07–18 页       成功结算       24
```

### 必须一致的统计口径

1. **本期已结算**只求和 `Ledger.kind == settle`，按结算事件时间分桶。`reserve` 不计为消耗；`release` 不当作退款收入；`grant` 单列发放。
2. 当前可用 = `balance - reserved`；当前余额、预占和可用是实时值，不能与历史消费相加。
3. 明细中的 `amount` 当前为正数，业务类型决定语义。使用“结算 24 点”“预占 48 点”“释放 12 点”比无说明的正负号更清楚。
4. **交付版本数**按本期交付的唯一任务／版本计数；复用已有结果不重复计数，免费交付单独标明，不计入已结算点数。无字任务不当作新交付译图。重新生成新版本可以形成新交付。
5. 翻译列表、趋势、模式分布按同一账户、时区和范围计算；旧数据缺模式时展示“未分类”，不猜测；时间范围明确起止日，例：2026-09-08 至 2026-09-14，Asia/Shanghai。
6. 图表显示零消费与数据加载失败的区别；失败保留“暂时无法读取”与重试入口，不返回零值。
7. 供应商成本、Token 和重试调用由运营管理查看，不放入面向读者的默认统计页。

草图示例：每日消费 36 / 42 / 24 / 68 / 40 / 50 / 60 点，共 320 点；其中常规 260 点、重绘 60 点。账户余额 1512 点，预占 24 点，可用 1488 点。各值仅用于检查版式与口径。

## 7. 多主题设计规范

### 文字与空间

| 对象 | 建议尺寸 |
| --- | --- |
| 页面标题 | 32–36px / 1.25，手机 28px |
| 重要书名、模块标题 | 20–24px / 1.4 |
| 正文、导航、输入、按钮 | 16px / 1.5–1.65 |
| 时间、次要标签、状态说明 | 14px / 1.5，状态不能低对比 |
| 统计数值 | 32–40px，等宽数字便于对齐 |
| 按钮与可点击区域 | 常规高度 44–48px；图标配名称或清晰的可访问标签 |
| 页面／卡片间距 | 32–48px / 20–24px |
| 卡片／输入圆角 | 18–20px / 10–12px |

采用系统中文无衬线字体（优先系统可用的苹方、微软雅黑等），避免新增字体下载依赖。字距正常，中文主体不使用全大写英文小眉题。正文对比度设计目标至少 4.5:1，控件边界与可见焦点目标至少 3:1；每套配色独立验证。柔和提示通过浅底与留白实现，不通过降低文字不透明度实现。

### 语义令牌

| 职责 | 建议令牌 | 晴空亮色示例 |
| --- | --- | --- |
| 页面底／卡片／次级面 | `surface.canvas` / `surface.panel` / `surface.subtle` | `#F5F7FB` / `#FFFFFF` / `#EDF1F6` |
| 正文／次要文字 | `text.primary` / `text.secondary` | `#202A3C` / `#5D6B7F` |
| 装饰分隔／控件边界 | `border.subtle` / `border.control` | `#DFE5EE` / `#7B889A` |
| 强调背景／浅强调底／浅底文字 | `accent.solid` / `accent.soft` / `accent.text` | `#2269BA` / `#EAF2FF` / `#225E9F` |
| 主按钮文字 | `text.onAccent` | `#FFFFFF` |
| 状态 | `status.success.*` / `status.warning.*` / `status.error.*` / `status.pending.*` | 独立的前景与浅底成对定义 |
| 焦点 | `focus.ring` | 与控件及所在背景分别验证 |
| 阅读画布 | `reader.canvas` | 独立于品牌色，提供纸白、浅灰、夜色 |
| 图表 | `chart.classic` / `chart.redraw` | 独立配对、保留文字图例与数值 |

主题预设：晴空蓝 `#2269BA`、樱花粉 `#B23F72`、薄荷绿 `#267B64`、鸢尾紫 `#6952BA`；这些是亮色主按钮候选值，深色外观使用各自适配值及按钮文字配对。卡片艺术封面不随主题改色。

颜色实现分为基础色板、语义职责、组件引用三层。组件不得直接引用 `pink` / `blue` 等主题名称。`appearance`（跟随系统／明亮／深色）、`accentTheme`、`readerBackground`、`textScale` 分别保存，设置带版本和默认回退。主题切换不改变布局或重新载入漫画。未来自定义色生成完整配对并检查可读性；不能只替换一个十六进制主色就视为完整主题。

## 8. 数据需求：可复用与可新增

| 设计数据 | 现有基础 | 需要的工作（尚未实现） |
| --- | --- | --- |
| 书名、来源、页数、阅读锚点 | 本地 `Chapter` 有 title / source / pages / pageId / relativeOffset | 前端重组展示即可，保留本地书架边界 |
| 封面、最近阅读时间、排序 | 可从本地页图和位置推导；`updatedAt` 并非专门的阅读时间 | 新增本地 `coverPageId`、`lastReadAt`、`libraryLayout`；翻译更新不应把书顶到最近阅读首位 |
| 不同语言、模式的可用译图数量 | 页任务与本地缓存已有基础 | 按有效性去重聚合；云端可用与本机离线可读分开 |
| 批次与稳定次序 | 服务端 `job_json` 已返回 `batch_id`、`ordinal` | 补齐前端 `Job` 类型；按批次聚合，不能只从当前分页假装得到完整批次 |
| 结算、结果有效性 | 服务端已有 `settlement`、`result_available`、`result_expired` | 补齐前端类型与呈现，不误把这些写成待新增的服务端字段 |
| 云端可读书名与页码 | 书名主要在本地，现有服务器档案缺阅读上下文 | 可新增按用户隔离的批次显示摘要、用户自定义标题与源页标签；原始路径／文件名不默认上传，缺失时使用中性批次名 |
| 跨批次、跨本地与云端统一记录 | 已有任务列表、批次和请求回执 | 新增服务端分组查询、汇总状态、游标分页；已有任务的复用关系需保留 |
| 按日期／模式的完整消费统计 | `/v1/me/usage` 为分页流水与余额，`Ledger` 有类型、金额、时间、关联任务 | 新增服务器聚合查询；对完整数据计算，不能只累加第一页 30 条 |
| 图表与统计可解释性 | 当前没有完整的读者统计契约 | 响应附带范围、时区、统计时间和口径版本；区分零、加载中、失败、部分旧数据 |
| 已交付、免费版本数量 | `Job` 有完成时间、版本、结算状态与输出引用 | 新增按交付事实的聚合，明确交付时间与结算时间不同 |
| 等待时间预估 | 目前无可靠预测 | 本轮不显示 ETA；只显示实际阶段和已完成页数 |

建议的新接口职责是“翻译记录分组”和“用量聚合”，具体路径待实现时按现有 API 风格确定。无需引入永久云书架、支付、内容推荐或用户画像来完成本次设计。

## 9. 交互验收与待定项

本次交付是风格文字与可切换设计草图，客户端运行结果和服务端接口均未改动。草图本地模拟的切换仅用于评审，不创建翻译任务、不消耗额度。

后续实现需重点验证：

- 1440 / 1024 / 768 / 390 / 320px 下书名与按钮无重叠，放大文字后优先重排；主要说明和状态不缩成小字。
- 两种列表排列切换后保留排序、位置与数据；封面失败有可读占位；空书架和原图缺失状态明确。
- 阅读器的翻页、原图／已有译图切换、面板开关、重开漫画保留页码及页内相对锚点；切换现有结果不发新任务。
- 首次进入看得到主要操作，鼠标、键盘、触屏都能恢复沉浸控制；焦点不被自动隐藏。
- 进行中、部分完成、失败、待核实、过期、未获取、离线分别呈现，不阻塞其他页。
- 翻译记录统一去重，未关联本地书架的服务端任务可找回；费用根据结算状态说明。
- 统计覆盖预占／结算／释放／免费复用／新版本、多批次复用、完整分页、时区边界；模式合计等于总计。
- 四种强调色在明暗外观下验证文字与焦点对比；阅读画布可独立选择。

建议评审重点：默认晴空蓝还是樱花粉、横向主导航的方向、大卡片密度、阅读控制条默认常显及主动进入沉浸的方式。这些均为建议，尚未视为用户定稿。
