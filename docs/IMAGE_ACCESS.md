# 公共图片读取

阅读器和原位翻译共用 [image-fetch.ts](../apps/extension/src/sources/runtime/image-fetch.ts)。图片发现只产生资源引用，完成权限检查、读取和解码后才可用于翻译。

## 读取规则

| 资源 | 读取方式 |
| --- | --- |
| HTTP(S) 图片 | 受信扩展上下文请求原始字节，检查实际图片域名权限 |
| Blob / Data | 在拥有该资源的页面上下文读取 |
| 已还原 Canvas | 经站点声明读取页面像素；绑定文档、元素和导航版本 |

封面可显式选择图片文档的同源读取，适用范围、限额与标签页生命周期见[网站适配规范](SITE_ADAPTERS.md#必须保持的约束)；不影响正文图片读取，也不在 HTTP 失败后自动切换通道。

- 由已校验的来源页与引用策略生成 Referer；站点通过 `image.headers` / `coverHeaders` 声明必要差异。原位入口读取图片属性和 meta，缺省采用 `strict-origin-when-cross-origin`，不回溯页面响应头。
- DNR 规则只匹配当前精确图片 URL，同 URL 请求由 Web Lock 串行隔离；锁名使用该精确匹配式的 SHA-256，避免 Safari 的 1024 字符限制。完成、失败和取消均清理。
- `webRequest` 仅在请求期间观察扩展自身的重定向响应头。不设插件跳转次数上限，每跳重查 URL 与权限；跨来源重新生成请求头。重复 URL 的循环跳转仍拒绝。图片请求在首个有效数据块前最多等待 30 秒，之后每收到非空数据块重新计时，连续 30 秒无数据则取消；持续传输的大图不因总下载时间超过 30 秒被中断，完成或取消均清理计时器。
- Cookie 仅由浏览器在授权的源站请求中使用，不传给翻译后端或代理。缺少权限、HTTP 拒绝、资源过期和解码失败分别返回可操作原因。
- 来源 HTTP 文本、二进制与图片响应含 `cf-mitigated: challenge` 时，返回专门的 Cloudflare 验证错误，不读取验证页正文；成功状态码及适配器允许的错误状态也不能绕过此检查。普通 403 不直接判为 CF。验证失败不触发自动章节刷新或反复重试；提示用户在同一浏览器打开来源网页完成验证，再手动重载。
- 扩展来源图片请求使用浏览器默认 HTTP 缓存策略，遵循源站缓存头，不强制 `no-store`；成功字节仍由应用缓存管理。浏览器缓存分区、Cookie、Referer 和响应 `Vary` 可能影响命中，不保证后台请求复用网页已加载的字节。私有翻译 API 与结果下载的缓存策略不受此规则改变。
- Canvas 导出是像素重新编码，摘要可能与原文件不同；受污染画布不能导出。`activeTab` 不等于所有图片 CDN 的权限，`no-cors` 不提供可读字节。
- `readSourceImage` 的完成值仍为 Blob；可选的下载观察者借用同一收集器的只读分块，在失败时收到失效通知，不获得源站凭据或新的访问入口。只有已授权、无需适配器 `decode` 的 HTTP 原图可发布分块，调用方不得修改或转移缓冲区；观察者异常不改变下载结果。增量预览、最终显示与已读边界见[单来源阅读](SIMPLE_COMIC_READING_DESIGN.md#阅读与恢复)。

## Safari 公开来源通道

Safari 扩展自身的 fetch／XHR 不应用 DNR Referer 修改。图片适配器可显式声明 `safariTransport: 'public-native'`；公开文本 GET 可逐次在 `context.request()` 中声明同一选项。仅 Safari 使用容器 URLSession，Chrome／Firefox 保留原通道。当前选择此能力的是 Pixiv、Comic PASH、DM5 图片及 DM5 图片地址接口；不是遇到 403 后自动重试的通用代理，不用于依赖浏览器 Cookie 的请求。

- 扩展先检查目标权限；只传 URL、经来源规则生成的 Referer 和响应种类。原生端仅接受 HTTPS GET（Debug 可访问回环 HTTP），不接受 Cookie、Authorization、请求体或调用方任意请求头；不使用系统凭据库、Cookie 存储或 HTTP 缓存。
- 原生端不跟随跳转。图片每跳返回扩展重新校验 URL、权限、循环与 Referer；文本接口直接报告重定向。Cloudflare challenge 和非成功 HTTP 响应只返回状态及必要响应头，不转移正文。
- 原生流写入应用临时目录，单图最多 32 MiB、文本最多 8 MiB，原生网络总期限仍为 25 秒；扩展侧沿用上述 30 秒无数据超时。全扩展最多两个此类传输，每次消息最多传 512 KiB 原始字节的 Base64，避免整图编码和 JSON 副本同时驻留。图片解码及应用缓存仍由现有管线负责；此原生通道不承诺下载中的渐进预览。
- 文件使用随机标识，按 Safari 提供的 profile 标识隔离；每个目录最多四个文件。完成或取消即删除并取消仍在运行的请求；异常退出残留在下一次原生请求时清理超过两分钟的文件，不保存 URL、Cookie 或响应头到文件。源站私有内容和签名 URL 不进入诊断日志。
- 相比浏览器取图，此通道多一次临时文件写入、读取与分块 IPC，且无法复用 Safari HTTP 缓存；成功结果仍复用应用缓存。iOS 27.0 模拟器中，6.54 MB Pixiv 原图取回及解码约 3.28 秒（单次网络样本，非性能基准）。原生方案的收益是能够发送所需 Referer；XHR、源站页面跨域 fetch 均未解决该样本。真机内存峰值、持续阅读吞吐和耗电仍待验证。

## 验证

构建插件后，按[公共脚本环境](../scripts/README.md#来源与阅读验收)运行：

```powershell
node scripts/verify_image_transport.mjs
```

检查 Referer、逐跳权限、跨来源请求头隔离、同 URL 并发、取消清理、失败重试和缓存恢复。页面资源另覆盖画布重绘、元素替换及导航失效；真实账户会话和浏览器原生权限需要独立验收。
