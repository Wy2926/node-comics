# 系统设置与请求保护

本次修复慢上传占用数据库连接、领取候选嵌套连接、反馈无预算的问题，并在管理后台新增“系统设置”。只有管理员可以读取和修改；设置保存在数据库，所有 API 副本使用同一份配置。

## 参数及生效规则

| 分组 | 参数 | 初始值 | 含义 |
| --- | --- | --- | --- |
| 上传保护 | 单账户上传并发 | 10 | 一个账户跨 API 副本同时接收或写入存储的上传数量 |
| 上传保护 | 全局上传并发 | 16 | 所有账户共享的上传数量上限；同一上传会话始终最多接纳一条流 |
| 上传保护 | 接收空闲超时 | 15 秒 | 包含首个字节的等待；空数据块不延长时限 |
| 上传保护 | 接收总超时 | 120 秒 | 持续慢发也不能无限延长的收流期限 |
| 上传保护 | 上传占位有效期 | 45 秒 | 接收和写入存储期间持续续租，进程退出后过期名额可重新使用 |
| 反馈保护 | 每分钟补充额度 | 30 条 | 每账户独立的令牌桶补充速度 |
| 反馈保护 | 突发容量 | 10 条 | 每账户可立即提交的新反馈数量 |
| 反馈保护 | 每日新反馈 | 100 条 | 按 UTC 日期计算，与翻译页数和提交清单预算分开 |

单账户上传并发不能高于全局并发，接收空闲超时不能超过总超时。页面和服务端都校验范围。设置保存后供后续请求读取；已接纳的上传继续使用接纳时的超时和续租快照，不因修改设置而中断。降低并发上限不会主动取消已接纳上传，在占用低于新上限前停止接纳新上传。

反馈设置变化不清零已使用的每日计数，也不重新填满令牌桶。相同幂等键与相同内容返回原回执，不重复创建、不消耗新反馈预算；相同键与不同内容仍为 409。不同键即使反馈内容相同，也必须消耗预算。超限返回 429，包含 `Retry-After` 和 JSON 的 `retry_after_seconds`。

环境变量 `UPLOAD_USER_CONCURRENCY`、`UPLOAD_GLOBAL_CONCURRENCY`、`UPLOAD_IDLE_TIMEOUT_SECONDS`、`UPLOAD_BODY_TIMEOUT_SECONDS`、`UPLOAD_INGRESS_LEASE_SECONDS`、`FEEDBACK_REQUESTS_PER_MINUTE`、`FEEDBACK_REQUEST_BURST`、`FEEDBACK_RECEIPTS_PER_DAY` 仅用于首次初始化。系统配置创建后，以数据库为准；重启或不同副本的环境值不会覆盖管理员保存的设置。

## 管理接口

- `GET /v1/admin/system-settings` 返回版本、完整参数、最近更新时间及更新管理员。
- `PUT /v1/admin/system-settings` 接受 `{ "expected_version": 1, "values": { ...完整参数... } }`。与读取版本不一致时返回 409 `SYSTEM_SETTINGS_CONFLICT`，避免两名管理员互相覆盖。页面保留草稿，要求重新读取最新版本再保存。
- 普通用户和未登录请求不能读写系统设置；响应不包含任何供应商、数据库或存储凭据。

## 上传与领取的实现边界

上传路由先释放认证依赖持有的数据库事务，再通过短事务获取跨副本门禁。收流、等待客户端和 R2 PUT 均不保留数据库连接；完成后重新校验当前门禁代次、资源所属账户、取消/到期状态和图片摘要，再提交上传状态。

门禁按账户及全局数量控制，通过令牌识别同一上传的新旧代次。旧请求不能释放或终结新请求。客户端断连、接收超时或取消会释放接收名额；已经开始的存储线程必须真正结束后才释放，其间继续续租。空闲/总超时保留原上传回执，允许在原会话有效期内重试；已上传、校验中和验证完成的合法重放直接返回回执，不再次收流或写存储。

候选领取复用调用方数据库 Session，不额外借第二条连接，也不隐式提交或回滚调用方事务。常规领取保持锁外选举、锁内复核；调用方已有待写数据时先取得调度锁，避免自动 flush 颠倒锁顺序。

## 数据库与验证

本次新增 `shared_0002_request_limits` 与 `shared_0003_system_settings` 增量迁移，基于现有 `shared_0001`。只新增请求门禁、反馈预算与系统设置表；不重置用户、任务、反馈、上传或账本，不访问图片对象。现有启动入口执行迁移，本轮没有连接或升级产品数据库。
