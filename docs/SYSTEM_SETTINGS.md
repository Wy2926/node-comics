# 系统设置与请求保护

管理后台“系统设置”统一维护翻译提示词、页数默认值、匿名每日预算、分钟准入、上传保护与反馈预算。只有管理员可以读取和修改；设置保存在数据库，API 与工作进程从同一份配置读取。

## LLM 翻译提示词

- `comic_translation_prompt`：单图与整本 PDF / ZIP 共用的漫画正文翻译规则。
- `comic_title_prompt`：漫画名查询的翻译规则。

两项均为必填纯文本，去除首尾空白后允许 1–8000 个 Unicode 字符，换行统一为 LF；拒绝控制字符（LF、Tab 除外）和无效代理字符。不使用模板插值，无需填写目标语言变量。后台显示完整可编辑规则，可对照已保存文本，或将服务端返回的推荐文本恢复到草稿；点击保存后才生效。默认文本由 [translation_prompts.py](../backend/app/translation_prompts.py) 唯一维护，前端不复制；旧数据库行缺少字段时只在读取时补默认值，不改版本、不写回，下次完整保存时持久化。提示词不通过环境变量覆盖。

推荐文本采用精简规则，不附大量示例或要求输出解释；8,000 是编辑上限而非默认长度。升级代码不会覆盖数据库中已保存的规则（包括先前保存的推荐版）；要采用新的精简版，应在后台恢复推荐并保存，管理员自定义内容不自动改写。

可编辑的是翻译语义规则；后端固定将目标语言指令放在最前，再接可编辑规则与逐段 ID、输入只作数据的契约，Schema 与响应校验不因配置改变。推荐规则简洁表达忠实自然、保留原意与人物语气、统一专名与术语，并结合上下文传达梗、双关和文化含义。单页只利用当前分组上下文，整本利用全部提供的页面；提示词不能补足未提供的跨页信息，也不能保证模型语义准确。

新受理的单图和整本正文任务将全部 17 种目标语言展开为本地名称与英文名称，例如 `한국어 (Korean)`、`日本語 (Japanese)`、`繁體中文 (Traditional Chinese)`；英文自身已是完整名称，使用 `English`。名称由后端 [languages.py](../backend/app/languages.py) 统一维护，在系统消息第一句直接要求 `Translate every input text into 한국어 (Korean).`，随后要求所有译文值使用目标语言，不再在末尾追加 `Target` 标签。两类正文共用目标指令构造；接口、任务、检查点与嵌字仍使用原语言代码。指令计入实际输入预算，不增加模型调用；旧任务继续其原协议的目标行和冻结规则，已付费响应不会因指令变化重发。漫画名查询是独立的开放语言代码接口，不受正文目标名称表限制。

保存只影响新受理的正文任务：受理时冻结完整有效提示词与协议版本，参与任务和结果缓存身份；同一 UUID 重放、分组、自动重试、重启和已付费响应恢复继续原快照。显式重新翻译／失败后新建重试任务按当前配置受理。没有提示词快照的升级前任务保留原内置提示词；整本旧请求保留 `comic-document-v2` 请求摘要，不用新规则自动重发。漫画名保持原共享别名缓存，修改仅影响缓存未命中的新查询，不删除或强制刷新已有缓存。

提示词不发送给图像计算节点或普通客户端。审计仅保存两项提示词的 SHA-256 和字符数，不记录全文。不要在提示词中填写密钥或私人漫画原文：有效提示词会发给所选 LLM，并随任务快照存储。正文每组和每次重试都会重复发送规则；长度增加会提高输入 token 与费用，成本预占使用实际冻结消息和 Schema 的 UTF-8 字节保守上界，整本同样计入上下文预检。后台保存不调用供应商，不代表真实翻译效果已验证。

## 参数及生效规则

| 分组 | 参数 | 初始值 | 含义 |
| --- | --- | --- | --- |
| 页数权益 | 普通每日页数 `free_daily_pages` | 30 张 | 新建每日额度桶的授予页数，已有桶不回写 |
| 匿名体验 | 每游客每日受理 `guest_daily_limit` | 5 张 | 同一游客身份的新受理常规翻译；整数范围 1–100 |
| 匿名体验 | 每网络每日受理 `guest_network_daily_limit` | 100 张 | 同一 IPv4 地址或 IPv6 /64 前缀的共享预算；整数范围 1–1,000 |
| 匿名体验 | 全站每日受理 `guest_global_daily_limit` | 10,000 张 | 全站匿名访客的新受理常规翻译合计；整数范围 1–100,000 |
| 翻译速率 | 普通用户新翻译图片 | 10 张 / 60 秒 | 全账户跨模式、语言和设备的精确滚动窗口 |
| 翻译速率 | PLUS 新翻译图片 | 100 张 / 60 秒 | 仅新受理翻译计数；重传、重放和结果复用不计数 |
| 上传保护 | 单账户上传并发 | 10 | 一个账户跨 API 副本同时接收或写入存储的上传数量 |
| 上传保护 | 全局上传并发 | 16 | 所有账户共享的上传数量上限；同一上传始终最多接纳一条流 |
| 上传保护 | 接收空闲超时 | 15 秒 | 包含首个字节的等待；空数据块不延长时限 |
| 上传保护 | 接收总超时 | 120 秒 | 持续慢发也不能无限延长的收流期限 |
| 上传保护 | 上传占位有效期 | 45 秒 | 接收和写入存储期间持续续租，进程退出后过期名额可重新使用 |
| 反馈保护 | 每分钟补充额度 | 30 条 | 每账户独立的令牌桶补充速度 |
| 反馈保护 | 突发容量 | 10 条 | 每账户可立即提交的新反馈数量 |
| 反馈保护 | 每日新反馈 | 100 条 | 按 UTC 日期计算，与翻译页数和控制请求保护分开 |

表中是代码默认初始值；空库首次配置可由环境变量覆盖。页数设置允许 0–1,000,000。每日额度修改不会重写已有桶的授予、已用或预占；运营会员已有段和续期保留原月额度，付费产品仍使用不可变权益版本。

匿名预算按 `QUOTA_TIMEZONE` 的自然日统计，独立于注册账户页数。保存新限额后，后续匿名受理使用当前限额与当天已用次数判断；修改不清零计数、不返还失败或取消任务的次数，也不取消已受理任务。同一 UUID 重放、本人有效在途或完成任务复用不再次计次；失败、取消、无字和部分完成仍计次。更换游客 Cookie 不重置网络或全站预算。配置缺少这三个字段时，读取使用表中的默认值，不改配置版本或写回数据库；下次完整保存时持久化。

单账户上传并发不能高于全局并发，接收空闲超时不能超过总超时。页面和服务端都校验范围。设置保存后供后续请求读取；已接纳的上传继续使用接纳时的超时和续租快照，不因修改设置而中断。降低并发上限不会主动取消已接纳上传，在占用低于新上限前停止接纳新上传。

反馈设置变化不清零已使用的每日计数，也不重新填满令牌桶。相同幂等键与相同内容返回原回执，不重复创建、不消耗新反馈预算；相同键与不同内容仍为 409。不同键即使反馈内容相同，也必须消耗预算。超限返回 429，包含 `Retry-After` 和 JSON 的 `retry_after_seconds`。

环境变量 `FREE_DAILY_PAGES`、`GUEST_DAILY_LIMIT`、`GUEST_NETWORK_DAILY_LIMIT`、`GUEST_GLOBAL_DAILY_LIMIT`、`FREE_IMAGES_PER_MINUTE`、`PLUS_IMAGES_PER_MINUTE`、`UPLOAD_USER_CONCURRENCY`、`UPLOAD_GLOBAL_CONCURRENCY`、`UPLOAD_IDLE_TIMEOUT_SECONDS`、`UPLOAD_BODY_TIMEOUT_SECONDS`、`UPLOAD_INGRESS_LEASE_SECONDS`、`FEEDBACK_REQUESTS_PER_MINUTE`、`FEEDBACK_REQUEST_BURST`、`FEEDBACK_RECEIPTS_PER_DAY` 仅用于首次初始化。系统配置创建后，以数据库为准；重启或不同副本的环境值不会覆盖管理员保存的设置。

## 管理接口

- `GET /v1/admin/system-settings` 返回版本、完整参数、`prompt_defaults` 推荐提示词、最近更新时间及更新管理员。
- `PUT /v1/admin/system-settings` 接受 `{ "expected_version": 1, "values": { ...完整参数... } }`。与读取版本不一致时返回 409 `SYSTEM_SETTINGS_CONFLICT`，避免两名管理员互相覆盖。页面保留草稿，要求重新读取最新版本再保存。
- PUT 必须提交表中全部参数及两个提示词字段；字段以 [RequestLimits](../backend/app/system_settings.py) 为准。成功更新在同一事务中写入操作者和前后值审计（提示词仅摘要），并通知客户端刷新策略。业务回滚时不留下成功审计。
- 普通用户和未登录请求不能读写系统设置；响应不包含任何供应商、数据库或存储凭据。

## 上传与领取的实现边界

上传路由先释放认证依赖持有的数据库事务，再通过 Redis 原子操作获取跨副本门禁。收流、等待客户端和文件落盘均不保留数据库连接；完成后重新校验当前门禁代次、资源所属账户、取消/到期状态和图片摘要，再提交上传状态。

门禁按账户及全局数量控制，通过令牌识别同一上传的新旧代次。旧请求不能释放或终结新请求。客户端断连、接收超时或取消会释放接收名额；已经开始的存储线程必须真正结束后才释放，其间继续续租。空闲/总超时保留原上传回执，在原请求仍允许补传时重试；已上传、校验中和验证完成的合法重放直接返回回执，不再次收流或写存储。

候选领取复用调用方数据库 Session，不额外借第二条连接，也不隐式提交或回滚调用方事务。常规领取保持锁外候选读取、锁内复核；调用方已有待写数据时先取得调度锁，避免自动 flush 颠倒锁顺序。

## 数据库与验证

数据库版本与保留数据升级规则见[部署规范](DEPLOYMENT.md)。短期准入计数存 Redis，配置值由数据库管理，见[请求保护](SUBMISSION_SCHEDULING.md)。分钟限额修改不清空窗口内已受理事件，实际准入使用当前配置重新计算；不取消已受理任务。分钟规则与日／月页数分别控制，每日页数按新建额度桶生效。管理与验证入口见[后台说明](ADMIN_CONSOLE.md)。

隔离验证覆盖上传连接池占用、超时/取消/断连、跨请求和跨账户并发、旧令牌保护、存储线程结束前的名额保留、默认连接池并发领取、反馈预算及幂等、管理员权限和配置冲突。正式部署的反向代理、共享文件卷、真实身份服务与容量验收单独验证。

可重复命令（在 `backend` 目录，先注入专用测试实例的 `TEST_REDIS_URL` 和 `TEST_PG_HOST / TEST_PG_PORT / TEST_PG_USER / TEST_PG_PASSWORD`，测试库名称固定为 `nodecomics_concurrency_test`）：

```powershell
$env:RUN_POSTGRES_CONCURRENCY='1'
$env:RUN_SCHEDULER_SCALE='1'
.venv/Scripts/python.exe -m pytest tests -q --tb=short
# 管理页面验收夹具，不读取生产环境文件：
.venv/Scripts/python.exe tests/manual_admin_server.py
```

未启用 PostgreSQL 的运行会跳过相关用例，不能代替上述完整并发证据。部署时需构建后台静态资源，并让全部控制进程使用同版本代码。
