# 翻译 API 简化实施说明

已按新契约实现客户端、服务端、数据库和管理诊断；无旧数据迁移或兼容接口。最终字段及恢复行为见[翻译接口契约](READING_TRANSLATION_CONTRACT.md)和 [OpenAPI](../contracts/openapi.json)。本次代码重构不代表已经发布插件、切换数据库或部署服务。

## 原问题与选择

旧客户端把两个 UUID、64 字符页面摘要与模式拼成 JSON `page_key`，常见长度 156，超过原接口 100 字符限制，会触发请求校验错误。失败的计划又可能让客户端继续续租不存在的阅读会话；现有源码支持这一原因，但没有据此声称已核实线上日志。

现在本地页面键压缩为固定 64 字符 SHA-256；服务端只接收 36 字符请求 UUID。客户端发送前保存请求，服务端永久记录业务摘要与受理结果。图片、模式和目标语言就是普通翻译的业务输入。

| 原流程 | 当前实现 |
| --- | --- |
| 整窗阅读计划、窗口序号、逐项操作回执 | 每张图片一个持久 UUID 资源 |
| 会话、续租、控制权和 epoch | 当前／预取提示与一次性短时优先 |
| 上传字节后 complete | 上传后自动校验和执行 |
| resolve、账户增量游标与策略同步 | 按 UUID 批量快照、ETag 和长轮询 |
| 成功后另查图片 access | 成功快照直接提供短期下载地址 |
| 客户端额度上限、策略种类控制 | 后端原子校验会员权益和分钟预算 |
| 旧迁移与旧本机数据 | 全新 `translations_0001` / `node-comics-reading-v2-*` |

## 保留的保证与取舍

后端仍管理任务持久化、上传保护、同级公平调度、分钟限频、会员额度和幂等结算。原图与译图保存在私有 R2，结果跨用户按内容复用且访问隔离。计算节点执行租约保障长任务恢复，与已删除的客户端阅读会话没有关联。

没有会话续租后，服务端不再知道每个浏览器精确的实时窗口；已受理的旧窗口请求继续完成，当前页只获得有期限的软优先。客户端负责合并快速翻页和停止隐藏页面的新请求。这样减少控制往返，也消除会话过期阻断正常翻译的问题。

失败、未知上游、无字结果和下载失败分别处理：普通滚动不重新生成失败页，未知重绘先核实，下载重试只刷新同一资源授权。签名地址不落盘，旧 UUID 的撤销记录不因新授权复活。

## 实施与验证范围

旧端点、会话表、策略版本、账户游标、旧操作模型及多余客户端协调逻辑直接删除；新数据库基线以最终模型生成。测试改为新资源契约，不使用 HTTP 兼容层。内部任务检查辅助仅用于执行器和结算测试。

验证入口、隔离数据库条件和浏览器脚本集中在[翻译接口契约](READING_TRANSLATION_CONTRACT.md#10-验证入口)。真实翻译效果、生产 R2 和公开部署不由模拟供应商测试代替。

- 新空库基线、OpenAPI 路由、文档链接与差异空白检查通过。临时 API、Vite 和隔离 PostgreSQL 已停止；截图与结果保留在 artifacts。
