# 翻译模型选择设计

状态：待实现。官网模型展示已使用统一公开目录；本文件定义插件、官网与后端的增量设计，不代表当前 API 已接受 `model_id`，也不代表真实上游模型已完成配置或验证。

## 1. 产品规则

模型选择只作用于 NodeLane 官方常规图片翻译的正文 LLM，不改变 OCR、图像处理、漫画名翻译或 MTU 的服务端配置。

| 模型 | 免费／游客 | PLUS | Pro | 有可用 PLUS 购买额度 |
| --- | --- | --- | --- | --- |
| GPT 6 Luna | 支持 | 支持 | 支持 | 支持 |
| Claude Haiku 5.5 | 支持 | 支持 | 支持 | 支持 |
| DeepSeekv4 Pro | 不支持 | 支持 | 支持 | 支持 |
| Gemini 3.8 Flash | 不支持 | 支持 | 支持 | 支持 |

PLUS 与 Pro 的模型集合相同，区别来自套餐实际页数等权益；不宣称 Pro 有独占模型、更好的译文或固定速度。模型名称为产品展示名，不是可以猜测的供应商 API model 参数。

选择器始终保留“自动选择（默认）”。不指定模型时使用当前服务端按权益筛选后的稳定加权分流，不固定成某个产品模型；旧插件无需升级即可沿用默认模式。明确选择一个模型时不能静默改用另一个模型。

模型访问资格、可用额度与扣费来源分别判断。免费模型不等于不计量；扣费顺序和购买额度的生效条件沿用[会员规则](MEMBERSHIP_AND_QUOTAS.md#1-权益模型)。付费额度耗尽、过期或撤销后不能仅凭会员名称或购买历史继续创建高级模型任务；免费赠送不授予高级模型权限。已受理任务、已有结果访问不因后来权益变化被重新收费。

## 2. 最小数据与权限边界

复用现有 `TranslationProvider`、不可变 `TranslationProviderRevision`、`text_plan_ids` 和权重配置，不另建一套“前端允许模型表”或新的执行池。

- 首版一个可选模型对应一条正文供应商配置。公开 `model_id` 使用这条记录已有的稳定 ID；它不是上游 `config.model`，也不是显示名称。客户端只保存服务端返回的 ID，不能硬编码四个模型的 API 名称。
- 配置的 `name` 成为公开模型展示名，上线前在后台核对为面向用户的名称，不夹带线路、账户、密钥或内部地址。更换成另一种产品模型应创建新 ID；修改价格、密钥或同模型的连接配置继续生成现有不可变版本。
- 候选只包含已启用、正文权重 `text_weight > 0`、渠道有效的配置；漫画名专用或零正文权重配置不公开为可选模型。
- 免费模型配置可适用于全部套餐，或明确覆盖 `guest/free/plus/pro`；高级模型只覆盖已授权付费服务档位。自定义套餐沿用后台 `text_plan_ids`，不由浏览器推断继承关系。
- 名称、可用性和扣费分类都来自同一份服务端候选配置。免费档判断沿用“全部套餐或包含 `free`”，对外可返回 `requires_paid`。公开目录只负责静态营销文案，不代替运行时权限。
- 首版不做同名供应商聚合、用户自定义上游或每模型单独价格。模型 ID 本身不是秘密；端点、API key、真实模型参数、内部版本、权重和运营成本不得出现在公开列表中。

当前 `provider_resolver(..., provider_id=...)` 的内部点选路径会绕过 `weight > 0` 条件。公开 `model_id` 必须在统一正文候选集合中按 ID 筛选，不能直接把请求值传入这条内部路径。客户端的 `provider_id`、`plan_id`、`text_plan_ids` 等字段继续拒绝。

## 3. API 增量

### 可选模型列表

扩展现有 `GET /v1/capabilities`，增加可选 `translation_models`，不新增逐页查询接口：

```json
{
  "translation_models": [
    {"id": "<服务端模型 ID>", "name": "GPT 6 Luna", "requires_paid": false, "available": true},
    {"id": "<另一模型 ID>", "name": "DeepSeekv4 Pro", "requires_paid": true, "available": false}
  ]
}
```

`available` 表示这次权益快照可选择，不是额度预占或服务完成保证。登录请求按当前账户计算，未登录按游客范围展示；游客次数仍来自现有匿名状态接口。付费项可置灰并说明需要相应权益；没有可用模型时不允许新建任务。列表与创建使用同一资格解析函数，创建时必须重新检查余额和权限。

字段缺失表示旧中心不支持选择，仅展示自动模式且不发送 `model_id`；空数组表示新中心当前没有候选，不能等同于旧中心。列表按账户／官方渠道缓存于当前连接，登录、换号、权益刷新或选择被拒绝时失效；复用已有刷新时机，不额外逐页轮询，不把上个账户的列表带到新账户。

### 新建、重试与重译

注册与游客的 `PUT /v1/translations/{id}`、`PUT /v1/guest/translations/{id}` 使用同一可选字段：

```json
{
  "image": {"sha256": "<实际送译字节摘要>", "byte_size": 123456, "content_type": "image/png", "normalization_version": 1},
  "mode": "classic",
  "target_language": "zh-Hans",
  "model_id": "<从当前列表取得的模型 ID>"
}
```

- 普通新建：省略或 `null` 表示自动；非空 ID 表示指定模型。空字符串、格式错误或未知字段返回 422。
- 新 UUID 的 `retry_of`：省略模型时继承来源请求的显式选择；来源未指定模型时保留原来的默认分流。不能借重试变更显式模型，不一致返回 409。新任务重新检查当前权限并冻结当时版本；同一 Job 内部重试仍使用原不可变版本。
- 新 UUID 的 `regenerate_of`：允许指定模型来重译。省略或 `null` 仍为自动，保留旧插件的现有行为；新界面若要沿用来源模型，明确发送该 ID。继续沿用未知成本确认、结果格式继承与新版本计量规则。
- GET 核实、同 UUID 重放、补传、SSE 续接、下载重试，不读取当前选择来修改原请求，也不生成新 UUID。

建议公开错误：`TRANSLATION_MODEL_NOT_ALLOWED`（403，权益不符）、`TRANSLATION_MODEL_UNAVAILABLE`（503，已停用／无可选配置）、`TRANSLATION_MODEL_INVALID`（422，格式不合法或未知 ID）。余额与受理限额继续使用现有额度错误和 429 `Retry-After`。已选模型不可用时提示用户重新选择，不能自动去掉字段重发。

### 请求身份与公开快照

`TranslationInput.model_id` 默认不进入 `model_dump`，只有非空显式选择才追加到请求摘要对象。不能直接增加默认 `null` 到现有摘要：目前 `accept_translation()` 对完整 dump 求哈希，会造成旧 UUID 重放冲突。必须用已保存旧请求摘要的回归用例验证逐字节兼容；不批量重算旧摘要。

显式选择参与请求身份，同 UUID 改模型返回 `IDEMPOTENCY_CONFLICT`。`priority` 等已弃用字段的现有忽略语义不变；不要全局改成 `exclude_none`，否则其他历史默认字段也会改变摘要。

在 `TranslationRequest.descriptor` 中增量保存请求的显式 `model_id`（仅有值时）和新受理时的公开实际模型快照 `{id,name}`。名称只作展示，不进入 Job 配置版本、图片身份或缓存键。快照响应增加可选 `requested_model_id`、`model`；旧请求缺少展示快照时显示“默认模型／历史任务”，不根据今天的配置伪造历史名称。

实际模型身份从已冻结的 `Job.config.text.provider_id/revision_id` 取得，不能回显客户端的未经验证名称。同 UUID 重放读取原 descriptor；同内容复用原 Job 也必须报告该 Job 的实际模型，不能报告当前随机选择器的其他结果。列表、批量查询与 SSE 沿用批量快照路径，不为每条记录查询当前供应商名称。

## 4. 服务端受理顺序

保持 scheduler → user 锁顺序和已有受理事务：

1. 校验请求形状、规范化可选模型，并优先查询当前用户的 UUID。已受理重放返回原记录，不因权益到期、模型停用或改名重新选模。
2. 读取一次正文候选配置和当前有效权益。自动模式执行原 `admission_policy` 与稳定加权路径；显式模式严格筛选所选 ID。
3. 使用所选模型能消费的权益确定准入策略。免费模型走免费 → 订阅 → 购买；高级模型走订阅 → 购买。不能让客户端指定扣费桶。
4. 用所选供应商不可变版本构造原配置与缓存键，查询本人在途及有效结果。已授权的本人复用不再次预占或结算。内容相同但供应商／版本不同不能复用；自动与显式最终落到同一个配置时可以复用，不额外把选择方式加入缓存键。
5. 仅新建实际任务时要求当下模型权限和可消费余额，执行原分钟／小时准入、额度预占、任务与回执提交。配置变更、权益撤销和并发耗尽必须在同一锁与事务边界生效。

显式选择不能只看 `membership_benefits.plan`，也不能先选任意一个额度包再假定所有包权限相同。扩展 `first_subscription`／`first_purchase` 的有界选择，让模型的服务档位条件进入 SQL 过滤，再按原顺序 `LIMIT 1`；订阅不适用或耗尽时才寻找适用的购买桶，不载入完整购买历史。列表可按少量唯一服务档位复用查询结果，不能每个模型重复扫描余额。

“有本人旧结果可读”不等于“可以新建该高级模型任务”。本人 GET、下载及已有 UUID 恢复保持有效；无权益的新选择不得借图片摘要访问他人结果。若新 UUID 匹配本人已完成结果，需先匹配所选配置并按现有本人复用规则返回，不能重扣页数；无可复用结果才执行新受理权限与余额拒绝。

## 5. 插件交互与本地身份

- 在现有翻译设置中，把“模型”放在目标语言旁；阅读器与网页原位翻译复用同一官方渠道选择。选项为自动、免费模型、付费模型，置灰项提示升级／额度不足。MTU 不显示官方选择器。
- 公共 `ChannelConnection` 只增加可选模型能力，`RuntimeOptions` 传递可选选择值；由 NodeLane 适配器解释和发送。公共 UI 不增加 `adapterId === 'nodelane'` 的执行分支，不新建每模型渠道、账户作用域或数据库。
- 选择偏好按官方中心 origin 与用户隔离；账号切换先重置并读取新账户偏好。已选项失效时保留可辨认的失效状态，要求用户选择自动或其他可用模型，不能静默替换。
- `operations.ts`、coordinator、state 查询共用一个模型感知操作键函数。自动模式保留现有 `operationId` 输入；仅显式选择追加模型 ID。请求创建前连同 UUID、实际送译字节身份一起持久化，原图摘要和目标页身份不改变。
- 切换模型只影响尚未形成请求的新任务。已受理、未知状态或正在补传的任务继续原 UUID；先核实这些记录，不能因为新的操作键找不到旧任务而重复提交。已成功译图继续可见，显示实际模型；替换译图需用户显式“用所选模型重新翻译此页”。
- `pageTranslation()`、任务到 `Job` 的转换和结果选择需携带模型元数据，不能把同语言的其他模型结果误标成当前选择。恢复查询仍跨当前选择发现本人旧任务；原图／译图切换、阅读位置和已缓存图片不清空。
- 保留有限阅读窗口、既有并发和缓存预算；选择多个模型的历史结果不意味着增加预取窗口或同时执行全部模型。

## 6. 官网工作台

语言选择旁增加同样的模型选择器，免费项与付费项分组；登录与游客身份切换后刷新资格，不混合历史。批量开始时冻结本批新任务的语言和模型；执行期间修改选择只影响下一批，不能改变正在编码或等待提交的本批记录。

`RecordMeta` 增加可选 `modelId`，与 `requestId` 一起冻结；缺字段的旧记录按自动恢复，不回填今天的偏好。提交从记录取值，断网恢复仍先 GET 原 UUID，只有明确 404 才发送原参数。重试来源只携带允许的 `retry_of` 形状，不能同时塞入 image 和新的选择来覆盖来源。

历史行显示实际模型，待受理记录显示所选／自动；下载使用已保存结果，不重新翻译。模型失效、余额不足、登录失败与普通网络失败分别提示；已有成功结果仍可下载。沿用每次 10 张、像素 Worker、历史数量与容量限制，不增加图片解码或模型探测请求。

## 7. 实现入口与验证

| 范围 | 主要入口 |
| --- | --- |
| 模型资格、默认路由 | `backend/app/translation_providers.py`、`providers.py`、`classic_config.py` |
| 受理、摘要、快照 | `backend/app/translation_api.py`、`jobs.py`、`schemas.py`、`main.py`、`guests.py` |
| 权益及扣费 | `backend/app/entitlements.py`、`billing_access.py` |
| 插件请求与恢复 | `apps/extension/src/translation/channels/adapters/nodelane/`、`channels/contracts.ts`、`reader/presentation.ts`、现有翻译设置 |
| 官网请求与历史 | `backend/website/src/components/TranslationWorkbench.tsx`、`lib/translation-api.ts`、`lib/translation-store.ts` |
| 机器契约 | [OpenAPI 维护入口](../contracts/README.md) |

必须覆盖：旧请求省略字段及显式 null 的摘要兼容；四模型资格；篡改模型 ID／套餐；零权重与停用；新建时并发耗尽、到期和撤销；订阅与不同服务档位购买桶的选择；免费模型优先扣免费额度；高级模型不扣免费额度；同 UUID 重放、原配置复用与不同模型不串结果；未知状态不重复请求；重试与显式换模重译；游客次数、账户和偏好隔离；切换模型后刷新、补传、SSE 恢复与下载；旧中心没有能力字段时的默认模式。

浏览器验收覆盖插件阅读器、原位翻译、官网批量任务及移动／RTL 布局；实际点击、键盘操作、截图与阅读位置恢复要单独检查。查询计数测试要求候选配置单次读取，列表不产生 N+1 查询；正文发送字节、执行并发与图像峰值内存不应因选择器改变。预计新增开销仅为小型模型列表和本地元数据；真实延迟、内存、吞吐及模型效果尚未测量。

发布顺序：后端与机器契约先支持可选字段并通过旧客户端回归，再发布官网和插件。缺少模型选择能力的旧中心不接收新字段；已产生显式模型请求后不能直接回退到拒绝该字段的中心，回退需保留受理／恢复接口或等待相关请求完成。生产模型地址、真实 API ID、许可、结构化输出、费用与真实图片翻译须另行验证，不能把本地假模型配置或 UI 检查当作接入完成。
