# 翻译文件存储与生命周期

本文规定当前[翻译集群](TRANSLATION_CLUSTER_DESIGN.md)的文件存储规则。翻译运行链路仅使用中心共享磁盘；覆盖层格式与接口见集群设计。结构迁移不操作旧远端对象。官网公开安装包使用发行清单中的永久下载地址，独立于翻译文件，见[部署规范](DEPLOYMENT.md#插件安装包)。

## 存储介质选择

采用**服务器文件保存图片二进制，PostgreSQL 保存业务状态与描述**。

| 方案 | 取舍 | 决策 |
| --- | --- | --- |
| 文件 + DB 元数据 | 可直接流式交付；需要处理文件与 DB 的提交窗口 | 采用 |
| PostgreSQL bytea / Large Object | 字节与结算可以同事务提交，但图片增加数据库、WAL、备份恢复负担 | 不作为默认 |
| Redis | 内存容量与任务/结果持久性要求不匹配 | 仅短期限流 |
| R2 / MinIO / 其他对象服务 | 增加网络中转和独立服务运维 | 新运行链路移除 |

PostgreSQL 能通过 TOAST 保存大字段，文件方案是对持续累计图像、直接下载和单中心拓扑的工程选择，不是数据库不能存图。[PostgreSQL TOAST](https://www.postgresql.org/docs/current/storage-toast.html)。不能以未测量的“补丁一定只有几 KB”为前提把图片都塞进 DB。

## 目录与部署边界

```text
/data/translation/
  inputs/<input-asset-id>/source
  results/<artifact-id-prefix>/<artifact-id>
  staging/<operation-id>.part
```

文件格式由数据库 MIME 指定，不依赖扩展名。路径只由服务端 ID 生成，不拼用户文件名/URL。输入为任务私有文件，结果为不可变产物，不做跨任务原图文件去重。目录中不保存官网安装包。

- API、control-worker、maintenance 挂同一中心宿主机持久卷和 UID；临时原图应跨进程/容器重启恢复，不能使用 RAM-only tmpfs。
- 根 Compose 和服务器 Compose 共用 `translation_files` 持久卷，三个进程的 `STORAGE_PATH=/data/translation`，`TMPDIR=/data/translation/staging`。
- staging 和最终目录在同一文件系统，支持原子发布；卷不公开为静态目录，不允许路径遍历。
- 同一宿主机可运行多 API 进程共享该卷。多台中心各自 local 并不共享，基线仅横向扩计算节点，多中心容灾另行设计。

## 数据模型

执行和交付使用 `Job`、`TranslationRequest`、`Asset`；租约、上传意图与文本检查点继续承担各自的恢复职责。不存在独立结果副本表、共享授权表、文件页匹配表或存储后端选择字段。

| 记录 | 内容 | 生命周期 |
| --- | --- | --- |
| 输入描述 | 送译 SHA-256、大小、格式、宽高、规范化版本 | 随请求/结果保存，不含原图字节 |
| 临时输入 | job、路径、写入代次、期限、可用状态 | 上传至任务终态清理 |
| 任务/租约 | UUID、节点、代次、期限、检查点、调用意图与结算 | 持久业务状态 |
| 结果产物 | ID、账户、representation、相对路径、摘要、大小、bbox、就绪状态 | 不依赖临时输入保存 |
| 请求/回执 | `TranslationRequest` 的本人 UUID 与 Job 关系、撤销状态；租约的冻结提交摘要和终态 | 访问与重放依据 |

OCR/译文继续存 DB，服务恢复和现有详情；中间背景/张量不新增持久文件。当前分析协议中的有界 mask 检查点可随分析保留，不另建图片服务。

`Asset` 保留输入描述，终态后删除其原图文件。结果 Asset 的 `parent_id` 仅关联输入描述，不延长原图保留，也不作为结果可读的文件前置条件。Job 保存冻结结果描述，无字结果保存描述和成功回执，不产生结果文件。

本人结果匹配键包含输入摘要、模式、语言、有效配置、规范化和格式版本。同 UUID 不受后来默认配置改变影响；下载只验证本人授权与产物，不尝试恢复输入。

## 文件发布与恢复

文件与数据库不能原子提交，输入/结果共用明确的发布流程：

1. 短事务建立上传/交付意图，记操作 ID、任务/租约代次、期望摘要和服务端最终路径。结果元数据与文件摘要一起冻结，同租约不同内容冲突。
2. 事务外有界流写独占 `.part`，核对实际长度、SHA-256、文件结构、容器声明尺寸和 bbox。过大、超时、摘要或结构错误立即停止，不在大传输中持有调度锁；完整像素校验由计算节点执行。
3. classic 结果完成校验后，在租约仍有效且未超过整页/交付最早截止时，先以短事务保存受理时间和截止快照。再 fsync 文件，同文件系统原子且不覆盖地发布，同步目录。已存在的最终文件只有属于同一冻结提交才复用；同步失败不报告成功。
4. 新短事务复核当前状态、执行代次与取消。classic 结果按已持久化的受理时间核对截止，及时受理后的本地落盘和提交可跨处理截止；无及时受理记录不能发布。输入 ready 才能调度；结果描述、产物关联、任务成功、一次结算和稳定回执一起提交。
5. 提交后通知并清理，失败由 maintenance 根据持久记录补偿，不把已成功任务改成失败。

multipart 只含一个有界 JSON 描述和至多一个文件：覆盖/整图必须有文件，无可见变化的 original 结果不得带文件。中心检查摘要、大小、整页尺寸、bbox、容器声明尺寸和格式，不解码图片；WebP 分块包作为一个不可变文件保留，块清单与校验见[计算协议](COMPUTE_PROTOCOL.md#webp-分块包)，不为每块增加文件或数据库记录。可信节点负责像素有效性、OCR/嵌字质量，文件校验不是效果验收。

| 故障 | 恢复 |
| --- | --- |
| 接收中断 | 操作租约到期后清理 part，同 UUID/租约重试 |
| 落盘后、DB 提交前崩溃 | 根据意图核对文件与代次；classic 还须有截止前校验完成的受理记录。已取消/被新代次取代不发布，及时受理后跨处理截止仍可恢复；单纯租约超时先协调恢复再清理 |
| DB 提交后回执丢失 | 先返回稳定回执，原图已删也不要求重传或二次扣费 |
| 旧代次晚到/异摘要 | 拒绝，不覆盖新结果，仅回收确定无有效引用的本次文件 |
| 在途原图丢失 | 暂停并允许同 UUID、同摘要补传，保留检查点与预占；补传到期失败释放 |
| 成功产物缺失/损坏 | 明确 RESULT_UNAVAILABLE，保留账本证据，优先备份恢复，不在 GET 内重算 |

租约超时不等于已被新代次取代。classic 首次及时受理后，以当前租约到期和受理时间加 `upload_body_timeout_seconds` 的较晚值固定本地落盘宽限；心跳与重放均不能延长，处理截止后的节点停止确认也不能撤销该宽限。恢复器在锁内检查同代次、及时受理记录及耐久文件，再补提交；旧节点自身不能凭过期令牌建立新受理记录。受理记录先于文件发布，避免文件已落盘却缺少期限证据的崩溃窗口。对同代次、未取消的耐久重绘产物尤其不能先删除再判定未知。若只有调用/摘要记录而无完整耐久字节，则核实供应商，禁止自动重调。

恢复补传不再次计分钟次数，与首次 needs_input 区分。未知付费重绘仍以 needs_attention 优先，补传不得重启调用。错误映射与恢复状态见翻译契约及 OpenAPI。

## 原图与结果清理

- **完成**：文件已耐久保存、终态事务成功后立即撤销输入读取并删除中心原图；节点获稳定回执后删原图、背景、mask 和冻结结果。不设置完成后继续保留若干天的正常路径。
- **失败/取消**：终态后撤销执行和输入访问、删除文件，节点停止清理。正在读写的操作有界退出；文件占用导致删除失败时延后重试，不永久保留。
- **在途/节点失联**：保留输入支持接管；排队、上传、执行、文本等待、交付与自动重试均有期限，不靠续租无限延长保留。
- **未知重绘**：仅在核实窗口保留必要原图，到期终结并删除，保留非图像成本证据；已冻结结果进入交付恢复，不再次执行模型。
- **补偿**：终态立即尝试清理，maintenance 至少每分钟处理待清理记录、过期 part 与确定失效的发布意图。不得仅凭“当前 DB 无引用”全盘删除，防止 DB 恢复后误删较新文件。
- **注册账户结果**：有效本人结果默认长期保留，无闲置 TTL；撤销一个 UUID 不影响本人其他有效引用，最后有效引用撤销后回收文件。先在事务中撤销可读状态再删文件，保留 UUID 墓碑和最小结算记录，防止旧请求复活。游客适用下面的 24 小时期限。

正常立即删除与崩溃后补偿分别度量。删除指应用文件解除引用，不承诺 SSD 层安全擦除；临时原图不进入默认日志或备份。

## 插件临时送译副本

- 仅实际缩小或压缩后的输入缓存到独立 `translation-inputs-v1` IndexedDB，按账户 scope 与实际送译摘要隔离；无需处理、同尺寸压缩无收益或可选编码产物超限时，复用符合字节限制的规范化来源页字节。必要缩放、解码失败与冻结输入恢复失败不能使用这一回退。请求 UUID、来源摘要、送译摘要与尺寸仍独立持久化，缓存不是任务状态。
- 复用现有 `ByteCache`，总预算 128 MiB，按 LRU 淘汰。普通磁盘写入失败不阻止提交，完整译图缓存预算为零也不阻止新翻译。原图、送译副本、完整译图可能暂时同时存在；该预算不代表浏览器解码内存峰值。
- 上传、重试和结果合成优先复用缓存；未命中时读取原图、按冻结尺寸重建，并核对来源与送译摘要。摘要不符明确失败，不替换请求 UUID，不自动重译；手动重试继承原请求的送译信息。重建会额外编码一次，不能保证跨浏览器版本得到同一字节序列。
- 客户端只核实当前有限阅读窗口，不为缓存回收追踪离屏请求或后台合成。完整译图在实际读取时合成并缓存，命中后直接读取；输入缓存不依赖任务终态或结果落盘回调，不做孤儿扫描。

## 容量与备份

### 官网本地历史与游客结果

- 官网 `nc-website-translations-v1` IndexedDB 保存元数据、原始文件、冻结送译副本和完整合成译图；元数据／图片分仓，列表不读取所有图片二进制。结果格式作为可选元数据与 UUID 一起冻结，缺省沿用普通覆盖，完整译图编码见[翻译契约](READING_TRANSLATION_CONTRACT.md#4-状态与结果)。总上限 256 MiB／200 条，不自动淘汰历史或在途输入。像素处理串行、一次最多选十张，每张源文件最大 32 MiB；图片尺寸和分块协商见[翻译契约](READING_TRANSLATION_CONTRACT.md#官网图片工作台)，本地字节预算不代表解码内存峰值。
- 首次新任务前必须成功保存 UUID、身份 scope 和送译副本；存储失败不创建远端任务。译图落盘失败提示立即下载，恢复仍核实原 UUID、不自动新建任务。完整译图命中后直接读取，不依赖服务端原图或覆盖层继续存在。
- 历史按注册账户／游客隔离，未提交草稿属于当前浏览器公共暂存区，登录不自动迁移已提交记录。游客 Cookie 过期后仍可查看本浏览器保存的完整译图，但不能借新会话恢复旧服务器任务。清理站点数据会丢失历史，不保证持久或跨设备同步。工作台“删除本地记录”仅删除本地副本，不取消服务器任务或清除审计记录。
- 游客服务器结果自任务终态起保留 24 小时；读取和复用同步检查期限，过期立即拒绝，maintenance 分批撤销 UUID、回收文件。原图仍在终态清理；本地完整译图不受该期限影响。游客读取走 `/v1/guest/translations/{id}/result`，由 HttpOnly Cookie 验证本人归属。

输入与结果保留单请求大小、超时和并发限制。`CLUSTER_RESULT_INGRESS_CONCURRENCY` 限制同时接收的结果请求，`CLUSTER_MAX_RESULT_BYTES` 限制单个结果字节数；这些限制不按剩余磁盘空间计算。每次发布写独立 part，fsync 后通过同文件系统硬链接原子发布且不覆盖；竞争者核对已存在文件的摘要，不依赖全局磁盘写锁。输入、结果和 part 使用同一文件系统；不要给 staging 使用独立 tmpfs。

不设置磁盘容量预留、低水位或按磁盘容量限制领取。部署环境保证文件卷空间；实际写满或不可写时返回 STORAGE_FULL / STORAGE_UNAVAILABLE，文件就绪前不结算，不通过删除在途输入或有效结果腾出空间。

备份 PostgreSQL 和结果目录，排除 inputs/staging。第一版通过短暂停止发布/清理后的配套备份或卷快照记录一致恢复点；数据库单独恢复不等于结果恢复。不可变结果可以增量备份，恢复后先核验一致性再启用清理。

中心进程重启可恢复；主机/磁盘损坏依赖备份，单中心不是高可用。临时原图丢失依靠客户端同摘要补传；来源失效且无本地缓存则无法自动恢复。多中心共享存储应由明确可用性需求驱动，不提前增加组件。

## 结果读取与权限

`GET /v1/translations/{id}/result` 先验证协议头、登录账户、未撤销的本人 UUID 与 Job 归属，再按内部 ID 打开文件分块返回。可用反向代理内部重定向加速，但不公开真实路径。

不签发 URL、不外部跳转、不将 Bearer 放 URL。返回准确 MIME、长度、强 ETag 和 `Cache-Control: private, no-store`；If-None-Match 也先鉴权再 304。扩展按账户和摘要管理自己的缓存，切换账户不复用前账户授权。

网页原位翻译由受信扩展获取并向页面展示 Blob/合成图，源站不接收账户头。节点输入认证与用户结果认证分离，租约令牌不能读取其他任务。

覆盖层含局部画面和译文，仍为私有内容；磁盘、DB 与备份遵守同样权限边界。日志不记录图片、OCR 全文、令牌或原始供应商错误；用户删除无法召回已合法下载的字节。
