# MangaCopy 来源适配与导入设计

日期：2026-09-14。状态：方案已确认，首轮已实现。当前功能、真实采集与未验证边界见[实现记录](COMIC_LIBRARY_IMPLEMENTATION.md)。

本文只定义MangaCopy如何接入[通用漫画作品管理模型](COMIC_LIBRARY_DESIGN.md)，以及详情页入口、范围选择、目录发现与图片获取。作品、章节、出版套系、卷册和内容版本的含义由通用模型确定。此前以“作品→源站分组→条目→图片”作为核心模型的方案已被替换；它只适合作为源站导入视图。

## 1. 已核实的来源事实

本次实地检查了《来自深渊》《碧蓝之海》详情页及话、卷、番外阅读页；来源截图、目录计数、代码现状和用户补充的data-src复核见[调研记录](evidence/mangacopy-design-observations.md)。这些是2026-09-14的样本观察，不是全站接口保证。

- 来源目录有“默认、单行本、其它汉化版、同人漫画、其他系列”等原始分组；每组可按“全部／话／卷／番外”筛选。
- 默认分组可能混排卷、话和番外；标题含“番外”的内容可能仍处在源站“话”筛选中。
- 目录存在分页；同一个章节链接会出现在“全部”和某个类型筛选面板中。
- 第73话的漫画容器核实到43个不同的data-src，与界面43页一致；当时22个src仍是同一占位图。
- 调研时的扁平Chapter书架已替换为通用作品模型，MangaCopy通过独立适配器接入；历史代码观察保留在调研记录中。

“单行本是分组”只描述这家网站的UI。在通用模型中，单行本有独立成册出版的含义；本适配器不能把网站分组直接升级为已确认出版系列。

## 2. 映射规则

| MangaCopy信息 | 先保存到哪里 | 可以提出的映射；不能擅自作出的结论 |
| --- | --- | --- |
| 漫画详情页、路径、作者与书名 | SourceCatalog及原始元数据 | 识别主要作品候选；跨来源身份需核对。目录中所有关联内容不保证都属于这一作品 |
| 默认、单行本等分组 | SourceCatalog原始分组 | 仅用于来源浏览与范围选择；“默认”不等于连载版本，“单行本”不足以确定出版社／版次／套系 |
| 话、卷、番外筛选 | SourceEntry.rawType | 分别作为章节形态、卷册形态或内容角色的映射线索，不能直接生成互斥的核心类型枚举 |
| 第X话与章节UUID | SourceEntry及ReadingCopy候选 | 可识别本来源的章节候选；UUID不是全局Chapter ID，编号不证明跨版本同一性 |
| 第X卷 | SourceEntry及Publication候选 | 可保留卷次和成册线索；不知道出版套系就留“版本未确认”，不与别处的第X卷强行合并 |
| 其它汉化版 | 原始分组＋副本信息 | 提示可能存在不同译本；译者、底本和修订未知时不自动确认ContentVersion |
| 同人漫画、其他系列 | 来源条目及待整理材料 | 可能对应独立作品或其他关系；不能直接当作原作品章节或原作品的另一版本 |
| 全部筛选及分页按钮 | 来源清单的显示状态 | 不生成新的作品、出版系列或重复章节 |
| 漫画容器内data-src | ReadingCopy的有序图片清单 | 提供原图候选地址；实际下载、解码、保存另行验证 |

原始来源ID、分组、类型、标题、顺序与采集时间保留。核心对象使用本地稳定ID，通过有证据的映射关联来源条目；同一来源既可能提供多个版本，也可能包含与主要作品相关的其他作品。

映射不足时允许导入可读副本并标记待整理，不强迫用户填完全部元数据。用户已确认的作品／卷册对应关系在重新导入和来源更新时保留；源标签改变只产生差异预览。

## 3. 详情页入口与范围选择

### 3.1 发起

2026-09-15 更新：MangaCopy 与其镜像 Copy4000 的 HTTPS 根域及子域已加入安装权限，详情页自动显示带 Node Comics 标识的入口。打开插件弹框自动发现当前目录，可刷新并选择导入范围；浏览器限制站点访问时提供授权重试入口。两个域名共用来源目录与章节身份，网络请求保留实际域名。完整操作与本地证据见[网页图片发现与加入漫画](WEB_IMAGE_IMPORT.md)。

已建立来源关联时显示“在插件中查看／管理导入范围”。重复发起补充原有范围，不重复创建源条目。多作品／版本映射尚不明确时打开归属预览，不简单依据同名书架条目自动合并。

范围选择使用插件完整页面，弹窗只负责发起。关闭弹窗不丢失选择或已经保存的导入任务。

### 3.2 发现目录

先识别来源目录与所有分组，再分别枚举分组条目。展示有依据的状态，如“正在读取默认目录，第2/3页”；总数未知时只报告已发现数量。

分组清单完整才开放该组“全部”；所有分组与分页均已核实完整才开放“来源目录全部”。部分失败仍能导入已确认条目，但显示“仅部分目录”；空目录、加载中、权限不足、结构不支持分别处理。

“来源目录全部”指本次快照中当前可访问的全部条目，不代表作品完结、版权方的完整目录、未来更新或所有条目都属于同一创作作品。

### 3.3 选择与归属预览

来源模式保留原站分组和类型筛选，以便读者对应原页面；管理模式按通用模型展示章节、卷册及版本。

支持本来源目录全部、本组全部、跨页全选筛选结果、实际条目起止区间、单独勾选／排除、仅新增。切换筛选、排序和分页不改变已选身份集合，显示其他分组中仍被选中的数量。起止项使用实际标题选择，不将“1—20”直接变成数组下标或猜测的话号。

默认预选主要来源分组，其他分组显式可选；这是来源选择默认，不定义作品的正文范围。提供明确的全目录快捷操作。

确认前显示：来源分组与数量、拟关联的作品／章节／出版卷册、仍待整理的条目、新增／补齐／已有副本。同人或其他系列不能静默归到主要作品；不同出版版本不自动删重。可以调整“新建候选作品／加入已有作品／暂存待整理”。

按钮使用准确文案，如“导入95个来源条目”；映射后分别统计话、卷册与副本，不将95项全部称为95话。导入后的作品卡片与目录布局遵循通用管理设计。

## 4. 图片清单与获取

2026-09-15 按最新确认取消自动滚动，优先读取网页 JS 已取得的完整图片数组。实际检查的 [comic_content_pass202508141534.js](https://s3.mangafunb.fun/static/websitefree/js20190704/comic_content_pass202508141534.js) 使用以下协议：

1. 页面内联脚本提供 `var cct` 和 `var contentKey`。`cct` 的 UTF-8 字节是 AES 密钥；`contentKey` 前 16 个字符的 UTF-8 字节是 IV，其余字符是十六进制密文。
2. AES-CBC／PKCS#7 解密后，UTF-8 JSON 为有序 `{url}` 数组。网站把数组长度写入 `.comicCount`，先添加 3 个 DOM 图片，再由滚动事件追加槽位；链接已在这之前完整取得。
3. 插件只提取上述字符串字面量，通过原生 Web Crypto 解密，不执行或复制网站 JS，不硬编码页面数据。验证数组、数量、地址协议和当前已显示槽位的顺序后，直接建立 `slot-0` 起的有序清单。

如果内联数据尚未到达，限定在 `.comicContent-list` 内读取 `img[data-src]` 的稳定 DOM 前缀并继续等待；全程不滚动、不触发滚动事件。密文格式、总数或槽位顺序冲突会报告明确错误，不宣称完整。`data-src` 为原图候选，`src/currentSrc` 可能为占位图。重复 URL 保留各自槽位，不根据占位图尺寸过滤页面。

用户指出的`.comicContent-list.comic-size-1`已在43页样本核实；另两个样本观察到comic-size-2和comic-size-3，适配器不能固定后缀。

初期第 1 卷／番外样本的 DOM 数量曾不足 166／27 页；最新验证已核实完整数据存在于上述加密数组。实际扩展在 DOM 均只有 3 页时分别获得第 73 话 43 页、第 1 卷 166 页、番外 27 页，来源页滚动位置均为 0。该协议是当前真实样本事实，不作为未来站点结构不变的保证。

链接发现完成与下载完成分别报告。已有链接立即进入逐页下载，发现与下载同时进行；不等所有图片渲染或整个清单到位才下载。每张原图仍须获取、验证、解码和保存。异常槽位不回退占位图，也不采集页面外广告。

采集中心与离线导入先预读代表章节的图片域名，让开始按钮在用户手势内请求准确的来源／CDN 权限，获准后才入队。拒绝授权不发起图片下载；后续新增 CDN 或从按需阅读自动触发的未知域名保留授权待办，不把权限不足记为采集失败。已知同来源图片域名在后续章节启动时一并复用。

建议两种模式：默认“导入目录，阅读时获取”，可选“同时下载所选原图”。总大小或总页数未知时如实显示待解析；已经下载的条目独立可读，失败项可补齐。下载不创建翻译任务、不预占翻译点数，原图也不因导入自动上传后端。

## 5. 身份、更新与断点

源条目去重以已验证的平台身份、来源目录身份及章节UUID等来源键为依据，不能按标题或完整CDN地址判断。首页推荐的别名域名必须实际验证后才统一身份、申请权限或宣称兼容。

同UUID的“全部／类型筛选”入口引用同一个源条目；不同来源身份的卷版和话版仅在对应关系得到确认后关联通用对象。图像字节相同可以按原有账户／语言／模式／配置条件复用译图，不代表正式版本相同。

检查来源更新先生成差异：新增条目、已关联内容的新副本、图片修订、原标签变化或来源不可见。源站部分目录失败不覆盖旧记录，不将未出现的条目直接判为下架；来源不可见不删除已保存的副本或改变作品完结状态。

已移除的条目保留排除记录，更新不自动加回。旧选择保存为条目身份快照，不因网站插入新话而扩张。映射到新作品或不同卷册时提供预览与撤销，不破坏既有译图和锚点。

采集操作、清单修订、逐页完成情况本地持久化。重复点击和多标签页复用操作；恢复只处理未完成部分。首轮由打开的插件页面协调，关闭弹窗可继续，关闭负责采集的页面／浏览器则暂停，重开恢复；不依赖service worker常驻。已经提交的翻译独立由后端管理。

章节待执行队列按来源目录、分组和条目顺序排列，当前章节内串行下载页面。点击顺序、更新时间和发现时机不改变这一顺序；正在运行的章节不被新加入任务抢占。暂停或失败的条目可单独恢复，已保存页面不会因重新读取的短前缀而丢失。登录、验证或权限问题提供恢复操作；失效图片地址重新解析并校验章节归属。不上传源站 Cookie 或令牌，不添加后端任意 URL 代理。

## 6. 来源验收边界

- 当前已核实：两个作品目录的分组／类型／分页，以及43页样本的data-src与占位差异；有截图和脱敏计数。
- 真实插件已通过：100条目录导入，第73话43页、第1卷166页、第九卷番外27页的完整获取与解码，番外浏览器重启后恢复及双阅读器互斥。再次实时解析两个目录得到100／116条。
- 未验证：原生权限弹窗、登录／验证码、真实图片地址到期后的完整恢复。隔离扩展测试副本预授权了观察到的CDN，正式构建仍按需授权；没有下载全部100个目录条目的原图。
- 实现时验证两个实时目录的完整性，不把本次82、104等数量写成永久断言；覆盖混排、小数编号和标签不一致。
- 范围选择验证跨页、跨组、重复入口、部分失败和已导入差集；所有映射必须符合通用管理模型，尤其不能将同人／其他系列默认为原作品的版本。
- 恢复验证关闭弹窗、刷新、关闭浏览器、暂停、双标签页与容量不足；已完成副本可读且不重复建对象。
- 直接按全新通用模型验收版本身份、收录关系、阅读位置和账户译图隔离，不包含旧数据迁移或任何兼容代码。网页能显示首图不能代替插件交付证据。

普通网页大图扫描仍可独立使用，但不得在MangaCopy整本流程失败时静默降级并显示“整本导入成功”。真实接入采用经观察的DOM和插件消息，不编造API端点或全站兼容能力；可重复测试命令见实现记录。
